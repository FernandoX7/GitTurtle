# File preview support

This is the finite support matrix for the September 2026 design and workflow milestone. It describes implemented support, not every format the operating system could open. Native acceptance and installed build identities belong in the milestone's native verification record. The [captured document contract](document-previews.md) gives the detailed PDF/text, Markdown resource and interactive model behavior.

## Detection and source identity

History, revision comparisons, Quick Open, and Working Changes share the worker's supplied-byte routing. Recognized image/container signatures take precedence over a misleading extension. Ordinary valid UTF-8 named `.png` stays source text. An image extension remains a decoder hint for empty, corrupt, or unrecognized binary image input. A filename alone never establishes that an Office, media, archive, or font container is valid.

Before and After retain separate names, modes, object identities, bytes, errors and presence. Missing is distinct from zero-byte content. A missing historical object never substitutes the current working file. Stored symlinks remain literal source and are never followed. Existing rename, mode, merge-parent and partial staging identities remain unchanged.

Verified local LFS objects use the existing bounded size/SHA-256 check. Missing objects retain their pointer and explicit download workflow; browsing does not download or smudge. Decoded LFS content has no partial staging actions. Neither image pixels, PDF pages/extracted text, rendered Markdown, geometry, metadata nor decoded UTF-16 text are ever used as a Git patch.

## Background work and resource lifetime

Mermaid uses the pinned MIT-licensed [native Rust renderer 0.3.1](https://docs.rs/mermaid-rs-renderer/0.3.1/mermaid_rs_renderer/) with its CLI/PNG features disabled. Parsing, bounded graph inspection, layout, generated-SVG validation and rasterization run on the worker with cancellation checks between phases/diagrams. Individual library parse/layout calls cannot be preempted; these are finite input/graph/output bounds, not a process-memory sandbox or hard deadline. The [vendored patch](../vendor/mermaid-rs-renderer/GITTURTLE-PATCH.md) disables the renderer's own disk font cache while retaining system-font/in-memory Unicode metrics. Fixed rendering configuration prevents source directives from changing the renderer environment.

Rendered Markdown uses the CommonMark/GFM syntax tree, including code fences inside supported lists and block quotes. Mermaid diagrams share their already prepared pixels with the Diagrams tab; opening either surface does not run a second layout. Diagram HTML labels, click actions, configuration/frontmatter, imported styles and embedded resources remain refused. Complete literal source remains available through source tabs and Copy source. The [document contract](document-previews.md#native-markdown-and-local-resources) describes images, links, bounds and staging separation.

Initial blob reads, source preparation, sniffing, container inspection, UTF-16 decoding, native image/PDF work and GPUI BGRA conversion run on the replaceable repository worker. Later PDF pages use a bounded serialized lane; interactive models use one active and one replaceable pending render pair, and explicitly followed local documents use a bounded read lane. Cancellation is checked between phases and sides, and generation checks reject obsolete output. Native codec calls are synchronous bounded-input calls; cancellation cannot preempt an individual system decoder call. No decoder is a process-memory sandbox or hard wall-clock deadline.

The immutable cache remains limited to 32 entries / 128 MiB. It counts original captured byte buffers, literal source buffers, metadata strings, render pixels and existing patch/split/partial models. PDF page caches retain prepared render buffers and selected-page text; the parent cache reserves the complete 16 MiB allowance per PDF side. Models account for retained triangles and frame reserves. Markdown accounts for source/blocks and prepared images/diagrams. Image comparisons retain RGBA, BGRA and bounded captured originals. UI `Arc`s and GPU textures may outlive cache eviction, so this is not a total process-memory cap. Uploaded image tiles are explicitly retired after their final cache/view/retained-inspection owner releases them; Back, page replacement and window close trigger coalesced cleanup without an idle polling loop. Mutable Working/Quick Open previews bypass the immutable cache. Errors/missing objects are not cached permanently.

GIF cache entries count every BGRA frame and timeline, plus retained first-frame
RGBA and original GIF bytes. Explicit playback uses native frame requests from
the painted comparison; paused or hidden previews have no animation timer loop.
Navigation snapshots pause the clock. Frame decoding checks cancellation and
time between bounded phases; a single codec call cannot be preempted.

Mesh previews independently cap source bytes at 32 MiB, decoded vertices at 300,000, triangles at 100,000, and FBX/OBJ nodes or 3MF object instances at 4,096. Rasterization allows at most 64 million candidate pixel samples per requested frame, including overlapping geometry. Interactive consumers retain geometry instead of eagerly rasterizing four fixed views. Coordinates must be finite and bounded. The [ufbx supplied-memory loader](https://docs.rs/ufbx/0.11.3/ufbx/generated/struct.LoadOpts.html) has separate 96 MiB temporary/result allocator limits, progress cancellation, disabled external-file loading and a callback that refuses every file open; native references stay on the worker stack. [stl_io](https://docs.rs/stl_io/0.11.0/stl_io/) reads supplied bytes. Dedicated 3MF decoding validates a non-ZIP64 directory with at most 2,048 entries / 2 MiB directory data before decompression, caps the root relationship at 64 KiB and model XML at 16 MiB / 650,000 nodes, disables DTDs, and bounds component depth to 32. It follows the [3MF core build and transform model](https://github.com/3MFConsortium/spec_core/blob/master/3MF%20Core%20Specification.md) using in-memory ZIP parts only. Model textures, material paths and linked resources are never opened. These bounds are not a process-memory sandbox or hard wall-clock deadline; cancellation is cooperative between parse, geometry and raster phases.

General STEP tessellation was evaluated against maintained Truck and Open CASCADE paths. The current worker implements bounded faceted geometry, analytic CSG primitives and mapped representation placements; it does not integrate general trimmed-surface tessellation or product-relationship assemblies. The [CAD investigation and exact supported entities](interactive-3d.md) record upstream licenses, API allocation/cancellation constraints, units, fidelity and remaining limits. A supported faceted or analytic example is not evidence of general STEP or manufacturing validation.

System preview is an explicit action. A serialized background handoff writes captured bytes into a newly created private temporary directory (0700) and read-only file (0400), with a fixed filename and an allowlisted/detected extension. Repository paths are never used as destinations. HTML/scripts and SVG source use text suffixes. macOS `/usr/bin/qlmanage -p` opens that captured copy. At most four viewers may be open through this process; each temporary directory is retained until its viewer exits and is then removed. Abrupt termination can leave a private OS temporary directory for OS cleanup; no repository or preference state is changed. Linux currently has no corresponding launcher and reports that limit explicitly.

PDFKit extracts only the selected page text from supplied data, with scoped native references, independent UTF-8 bounds and explicit absent/truncated text. CoreGraphics uses an in-memory CFData provider and page graphics only; it does not invoke PDF actions, JavaScript, launch links or URL loading. ImageIO uses in-memory source data and bounded thumbnail options. [Apple's ImageIO source APIs](https://developer.apple.com/documentation/imageio/cgimagesource) and [CoreGraphics page rendering](https://developer.apple.com/documentation/coregraphics/cgcontext/drawpdfpage(_:)) define these native primitives. Rich external application behavior is owned by system Quick Look, not counted as an in-app renderer.

## Behavioral evidence and native cases

`cargo test --locked -p gitturtle-preview` covers actual raster output for PNG/JPEG/WebP/GIF/BMP/TIFF/ICO, generated HEIC/AVIF fixtures, alpha and orientation, selected PDF page order/pixels and text, page/output/source/text bounds, cancellation, corrupt data, SVG resource refusal, LFS pointer identity, strict UTF-16, WAV metadata, ZIP directory bounds and sfnt names. The HEIC/AVIF fixtures' generation provenance is in [their README](../crates/preview/tests/fixtures/README.md).

Worker tests exercise image content under an extensionless path, literal source under `.png`, captured SVG source, old/new renamed media bytes versus a different current working file, a missing object beside a readable metadata or rendered image side, stored image-named symlinks, shared Quick Open/Working media routing, local LFS retry and cache accounting. Captured-copy tests inspect exact bytes, safe path construction and filesystem permissions.

The earlier preview milestone's native checklist included BMP/TIFF/ICO, HEIC/AVIF, first-eight-page PDF navigation, captured source copying, metadata, captured-byte system preview, hidden-view return and appearance/focus checks. That historical checklist does not establish acceptance of the current on-demand PDF, native Markdown or interactive model implementation.

Current focused app tests cover PDF page/text cache eviction and late-result rejection, linked/independent model cameras and bookmarks, bounded render replacement, Markdown AST/literal HTML behavior, and distinct historical/index/working image bytes. Core resource fixtures cover literal paths, captured commit/document identity, raw helper-free reads, symlink refusal, budgets and cancellation. Decoder fixtures cover curved analytic STEP solids, mapped placements, unit conversion, shared camera scale and bounds. These tests are separate from native interaction evidence.

Current native acceptance includes page entry beyond page eight, differing PDF counts and selected-page text; native Markdown prose/images/links with exact-source staging; model orbit/pan/zoom/fit/views/wireframe and shared scale; cancellation during Back/Projects/tab changes; keyboard/focus and appearance; and resource cleanup. The [milestone record](next-milestone.md) and [validation guidance](validation.md#current-validation-guidance) own exercised source/build identities and outcomes. No native or platform pass is inferred from decoder tests.
