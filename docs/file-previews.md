# File preview support

This is the finite support matrix for the September 2026 design and workflow milestone. It describes implemented support, not every format the operating system could open. Native acceptance and installed build identities belong in the milestone's native verification record. The [captured document contract](document-previews.md) gives the detailed PDF/text, Markdown resource and interactive model behavior.

## Detection and source identity

History, revision comparisons, Quick Open, and Working Changes share the worker's supplied-byte routing. Recognized image/container signatures take precedence over a misleading extension. Ordinary valid UTF-8 named `.png` stays source text. An image extension remains a decoder hint for empty, corrupt, or unrecognized binary image input. A filename alone never establishes that an Office, media, archive, or font container is valid.

Before and After retain separate names, modes, object identities, bytes, errors and presence. Missing is distinct from zero-byte content. A missing historical object never substitutes the current working file. Stored symlinks remain literal source and are never followed. Existing rename, mode, merge-parent and partial staging identities remain unchanged.

Verified local LFS objects use the existing bounded size/SHA-256 check. Missing objects retain their pointer and explicit download workflow; browsing does not download or smudge. Decoded LFS content has no partial staging actions. Neither image pixels, PDF pages/extracted text, rendered Markdown, geometry, metadata nor decoded UTF-16 text are ever used as a Git patch.

## Support matrix

System preview, wherever the matrix names it, opens an isolated read-only copy of the captured bytes in another application, and only on an explicit click. On macOS it is **System preview** in Quick Look, offered for any captured bytes. On Linux it is **Open in default app**: the desktop's default application, reached through the OpenURI portal or `xdg-open` where no portal answers, offered only for a passive type that the bytes themselves establish (the raster images below and PDF, and plain text where a view presents a file's captured text as a document: the Diagrams view of a Mermaid file or of Markdown with Mermaid diagrams, and a text 3D model's header; never a source diff, the source tabs or Markdown's Rendered view), never for what the file is called, and opened only when the desktop's own type check agrees. Linux offers nothing for audio and video, office documents (OOXML and OpenDocument), SVG, HTML, XML, scripts, desktop entries, executables, archives (plain ZIP and JAR included), fonts, legacy Office, UTF-16 or unrecognized bytes. [Background work](#background-work-and-resource-lifetime) gives the rules for both.

## Background work and resource lifetime

Mermaid uses the pinned MIT-licensed [native Rust renderer 0.3.1](https://docs.rs/mermaid-rs-renderer/0.3.1/mermaid_rs_renderer/) with its CLI/PNG features disabled. Parsing, bounded graph inspection, layout, generated-SVG validation and rasterization run on the worker with cancellation checks between phases/diagrams. Individual library parse/layout calls cannot be preempted; these are finite input/graph/output bounds, not a process-memory sandbox or hard deadline. The [vendored patch](../vendor/mermaid-rs-renderer/GITTURTLE-PATCH.md) disables the renderer's own disk font cache while retaining system-font/in-memory Unicode metrics. Fixed rendering configuration prevents source directives from changing the renderer environment.

Rendered Markdown uses the CommonMark/GFM syntax tree, including code fences inside supported lists and block quotes. Mermaid diagrams share their already prepared pixels with the Diagrams tab; opening either surface does not run a second layout. Diagram HTML labels, click actions, configuration/frontmatter, imported styles and embedded resources remain refused. Complete literal source remains available through source tabs and Copy source. The [document contract](document-previews.md#native-markdown-and-local-resources) describes images, links, bounds and staging separation.

Initial blob reads, source preparation, sniffing, container inspection, UTF-16 decoding, native image/PDF work and GPUI BGRA conversion run on the replaceable repository worker. Later PDF pages use a bounded serialized lane; interactive models use one active and one replaceable pending render pair, and explicitly followed local documents use a bounded read lane. Cancellation is checked between phases and sides, and generation checks reject obsolete output. Native codec calls are synchronous bounded-input calls; cancellation cannot preempt an individual system decoder call. No decoder is a process-memory sandbox or hard wall-clock deadline.

The immutable cache remains limited to 32 entries / 128 MiB. It counts original captured byte buffers, literal source buffers, metadata strings, render pixels and existing patch/split/partial models. PDF page caches retain prepared render buffers and selected-page text; the parent cache reserves the complete 16 MiB allowance per PDF side. Models account for retained triangles and frame reserves. Markdown accounts for source/blocks and prepared images/diagrams. Image comparisons retain RGBA, BGRA and bounded captured originals. UI `Arc`s and GPU textures may outlive cache eviction, so this is not a total process-memory cap. Uploaded image tiles are explicitly retired after their final cache/view/retained-inspection owner releases them; Back, page replacement and window close trigger coalesced cleanup without an idle polling loop. Mutable Working/Quick Open previews bypass the immutable cache. Errors/missing objects are not cached permanently.

GIF cache entries count every BGRA frame and timeline, plus retained first-frame
RGBA and original GIF bytes. Explicit playback uses native frame requests from
the painted comparison; paused or hidden previews have no animation timer loop.
Navigation snapshots pause the clock. Frame decoding checks cancellation and
time between bounded phases; a single codec call cannot be preempted.

Mesh previews independently cap source bytes at 32 MiB, decoded vertices at 300,000, triangles at 100,000, and FBX/OBJ nodes or 3MF object instances at 4,096. Rasterization allows at most 64 million candidate pixel samples per requested frame, including overlapping geometry. Interactive consumers retain geometry instead of eagerly rasterizing four fixed views. Coordinates must be finite and bounded. The [ufbx supplied-memory loader](https://docs.rs/ufbx/0.11.3/ufbx/generated/struct.LoadOpts.html) has separate 96 MiB temporary/result allocator limits, progress cancellation, disabled external-file loading and a callback that refuses every file open; native references stay on the worker stack. [stl_io](https://docs.rs/stl_io/0.11.0/stl_io/) reads supplied bytes. Dedicated 3MF decoding validates a non-ZIP64 directory with at most 2,048 entries / 2 MiB directory data before decompression, caps the root relationship at 64 KiB and model XML at 16 MiB / 650,000 nodes, disables DTDs, and bounds component depth to 32. It follows the [3MF core build and transform model](https://github.com/3MFConsortium/spec_core/blob/master/3MF%20Core%20Specification.md) using in-memory ZIP parts only. Embedded GLB base-color PNG/JPEG textures are decoded under independent image and mipmap limits; external material paths and linked resources are never opened. These bounds are not a process-memory sandbox or hard wall-clock deadline; cancellation is cooperative between parse, geometry and raster phases.

General STEP tessellation was evaluated against maintained Truck and Open CASCADE paths. The current worker implements bounded faceted geometry, analytic CSG primitives and mapped representation placements; it does not integrate general trimmed-surface tessellation or product-relationship assemblies. The [CAD investigation and exact supported entities](interactive-3d.md) record upstream licenses, API allocation/cancellation constraints, units, fidelity and remaining limits. A supported faceted or analytic example is not evidence of general STEP or manufacturing validation.

System preview is an explicit action. On macOS a serialized background handoff writes captured bytes into a newly created private temporary directory (0700) and read-only file (0400), with a fixed filename and an allowlisted/detected extension. Repository paths are never used as destinations. HTML/scripts and SVG source use text suffixes. macOS `/usr/bin/qlmanage -p` opens that captured copy. At most four viewers may be open through this process; each temporary directory is retained until its viewer exits and is then removed. Abrupt termination can leave a private OS temporary directory for OS cleanup; no repository or preference state is changed.

On Linux, whether a side offers Open in default app is decided on the worker when the side is prepared, from its bytes alone ([`system_preview::passive`](../crates/app/src/system_preview/passive.rs)); the same decision fixes the suffix the copy is written with, and the repository's file name is never used. A leading signature establishes an image or PDF type. Text qualifies only as strict UTF-8 with no control characters other than tab, line breaks and form feed, no `#!` line, no desktop entry group, and no markup: nothing that begins with `<`, and none of the HTML, SVG or XML tags content sniffers search for in the first 4 KiB. Text is written as `.txt` and handed over only through the portal; `xdg-open`'s generic mode types a file by its content, so it never receives text.

Audio and video offer nothing on Linux, and a later change can revisit that only with a sandboxed or network-restricted player handoff. The default player probes the content rather than trusting its type, and both of its fallbacks reach the network from repository-chosen bytes: FFmpeg's SDP demuxer outscores most containers wherever a line starts with `c=IN IP` (an ID3 tag also moves where FFmpeg starts probing), so mpv, Omarchy's default player, opens RTP sockets at an address and port the copy names; and when FFmpeg cannot open a copy (an MP3, Ogg, MPEG-4, WAV or FLAC signature over an ISO 9660 image, or an empty ID3 tag before a ZIP), mpv retries at its unsafe level through libarchive, plays a playlist inside and requests its `http` URLs, which its ytdl hook also hands to yt-dlp. GIO types such copies by their suffix, so no type check sees them, and neither detecting archives nor predicting whether FFmpeg will open a copy is a sound rule.

Office documents offer nothing on Linux, and a later change can revisit that only with a bounded scan of the document bodies and a release measurement of its cost on every prepared side. Their bodies reach outside the package where no bounded check of the manifests sees it: Word field codes in `w:instrText` or `w:fldSimple` (`INCLUDEPICTURE` with `\d`, `INCLUDETEXT`, `LINK`, `IMPORT`, `DATABASE`, `DDE`, `DDEAUTO`), Excel web and database queries in `xl/connections.xml` with `refreshOnLoad`, `ddeLink` and `oleLink` in external-link parts, and in OpenDocument an XLink on any element under any prefix (linked images, objects, floating frames, section and table sources, sounds, fonts) and DDE, database, form and script declarations. Even the manifests are not a sound basis: a ZIP Unicode Path extra field (0x7075) makes the zip crate read an entry under a different name from the one office suites use (a `word/_rels/document.xml.rels` that the crate sees as `word/media/image1.bin`), and a package can declare a missing Word main part while holding a complete OpenDocument text.

A click writes the copy on the serialized background writer under `$XDG_CACHE_HOME/gitturtle/captured-copies` (else `~/.cache/gitturtle/captured-copies`): a 0700 root that must be this user's own directory and not a symlink, a 0700 folder per running GitTurtle holding an exclusive lock, and a fresh randomly named folder per click with `Captured revision.<suffix>` created exclusively at 0400 without following symlinks. The folder is made read-only (0500) once the copy is in it, so a handler's Save or Save As, which starts there, cannot leave the user's edits where eviction or quitting would delete them; it becomes writable again only to be removed. The portal's `OpenURI.OpenFile` receives a read-only descriptor of exactly that file, and picks the application by the type GIO gives it. GIO reads the suffix only when one type alone claims it (`*.txt`, `*.pdf`); for a suffix that several types claim (`*.png` by PNG and APNG, `*.ogg` by six) it sniffs the content, and magic of priority 80 or more wins over the leading signature, so a PNG whose text chunk holds an SVG document types as `image/svg+xml`, which a browser opens with its script. Before every portal request `gio info -a standard::content-type` therefore runs on the copy, from four fixed system paths, with no shell, the copy's folder as working directory, the session environment without `GIT_` variables plus `GIO_USE_VFS=local`, its own process group (killed whole after five seconds) and an answer read up to 16 KiB; the copy goes to the portal only when GIO's type is one of its kind's media types, and otherwise the line beneath the control names that type (an SVG or HTML document by name as well). Without `gio`, nothing opens. Only when no portal service or OpenURI interface exists does `xdg-open` run, from four fixed system paths (never `PATH`), with the copy's path as its one argument, no shell, the copy's folder as working directory, no standard streams, its own process group and the session environment without `GIT_` variables. Because `xdg-open` types a file with `xdg-mime query filetype`, which sniffs content and can type a polyglot by a later signature (an Ogg stream with an ISO 9660 descriptor is a disk image to libmagic), `xdg-mime` runs first, from fixed system paths and in the same way as `gio`: the copy opens only when the type it reports is one of its kind's media types and that type has a default application (without one, `xdg-open` would go on to mailcap, `mimeopen` and web browsers). Otherwise nothing opens and the line names the type `xdg-open` would have used. A portal that answered, refused or was cancelled, or a request that may still be in progress, is never followed by a second attempt; a portal that has not answered within two minutes is reported as unfinished, and an `xdg-open` that exits within two seconds reports its documented status. At most four portal requests or foreground `xdg-open` launchers run at once. A running GitTurtle keeps at most eight copies and 128 MiB, removing its oldest first, so a handler that reopens an evicted copy later finds it gone; quitting removes that session's copies, and the next launch removes the folders of sessions whose lock is free and abandoned staging folders, inspecting at most 1,024 entries and never following symlinks. The control itself answers each click, never the window-wide notice: it reads Opened for 1.5 s once something opened, and otherwise a line beneath it says why nothing did, a failure in the warning color or, for a request the portal reports cancelled (a closed application chooser, whether or not it offered an application, which the portal does not tell apart), a muted "Nothing opened." (see [DESIGN.md](../DESIGN.md#documents-media-and-exact-source)).

PDFKit extracts only the selected page text from supplied data, with scoped native references, independent UTF-8 bounds and explicit absent/truncated text. CoreGraphics uses an in-memory CFData provider and page graphics only; it does not invoke PDF actions, JavaScript, launch links or URL loading. ImageIO uses in-memory source data and bounded thumbnail options. [Apple's ImageIO source APIs](https://developer.apple.com/documentation/imageio/cgimagesource) and [CoreGraphics page rendering](https://developer.apple.com/documentation/coregraphics/cgcontext/drawpdfpage(_:)) define these native primitives. Rich external application behavior is owned by system Quick Look, not counted as an in-app renderer.

## Behavioral evidence and native cases

`cargo test --locked -p gitturtle-preview` covers actual raster output for PNG/JPEG/WebP/GIF/BMP/TIFF/ICO, generated HEIC/AVIF fixtures, alpha and orientation, selected PDF page order/pixels and text, page/output/source/text bounds, cancellation, corrupt data, SVG resource refusal, LFS pointer identity, strict UTF-16, WAV metadata, ZIP directory bounds and sfnt names. The HEIC/AVIF fixtures' generation provenance is in [their README](../crates/preview/tests/fixtures/README.md).

Worker tests exercise image content under an extensionless path, literal source under `.png`, captured SVG source, old/new renamed media bytes versus a different current working file, a missing object beside a readable metadata or rendered image side, stored image-named symlinks, shared Quick Open/Working media routing, local LFS retry and cache accounting. Captured-copy tests inspect exact bytes, safe path construction and filesystem permissions. On Linux, `system_preview` tests cover the content-decided allowlist and its refusals, offers decided on the worker for image and metadata sides, the store's modes, symlink refusal, bounds and stale-session cleanup, portal-error classification, the GIO and `xdg-mime` type checks (with stand-in answers, and with the installed `gio` on generated PNG polyglots), and the launcher's argument array, working directory, streams, process group and environment.

The earlier preview milestone's native checklist included BMP/TIFF/ICO, HEIC/AVIF, first-eight-page PDF navigation, captured source copying, metadata, captured-byte system preview, hidden-view return and appearance/focus checks. That historical checklist does not establish acceptance of the current on-demand PDF, native Markdown or interactive model implementation.

Current focused app tests cover PDF page/text cache eviction and late-result rejection, linked/independent model cameras and bookmarks, bounded render replacement, Markdown AST/literal HTML behavior, and distinct historical/index/working image bytes.
