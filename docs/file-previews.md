# File preview support

This is the finite support matrix for the September 2026 design and workflow milestone. It describes implemented support, not every format the operating system could open. Native acceptance and installed build identities belong in the milestone's native verification record.

## Detection and source identity

History, revision comparisons, Quick Open, and Working Changes share the worker's supplied-byte routing. Recognized image/container signatures take precedence over a misleading extension. Ordinary valid UTF-8 named `.png` stays source text. An image extension remains a decoder hint for empty, corrupt, or unrecognized binary image input. A filename alone never establishes that an Office, media, archive, or font container is valid.

Before and After retain separate names, modes, object identities, bytes, errors and presence. Missing is distinct from zero-byte content. A missing historical object never substitutes the current working file. Stored symlinks remain literal source and are never followed. Existing rename, mode, merge-parent and partial staging identities remain unchanged.

Verified local LFS objects use the existing bounded size/SHA-256 check. Missing objects retain their pointer and explicit download workflow; browsing does not download or smudge. Decoded LFS content has no partial staging actions. Neither image pixels, PDF pages, metadata nor decoded UTF-16 text are ever used as a Git patch.

## Background work and resource lifetime

Mermaid uses the pinned MIT-licensed [native Rust renderer 0.3.1](https://docs.rs/mermaid-rs-renderer/0.3.1/mermaid_rs_renderer/) with its CLI/PNG features disabled. Parsing, bounded graph inspection, layout, generated-SVG validation and rasterization run on the worker with cancellation checks between phases/diagrams. Individual library parse/layout calls cannot be preempted; these are finite input/graph/output bounds, not a process-memory sandbox or hard deadline. The [vendored patch](../vendor/mermaid-rs-renderer/GITTURTLE-PATCH.md) disables the renderer's own disk font cache while retaining system-font/in-memory Unicode metrics. Fixed rendering configuration prevents source directives from changing the renderer environment.

Markdown diagram extraction recognizes closed backtick or tilde line fences of at least three matching characters, indented at most three spaces, with `mermaid` as the complete information string. It skips fences within another fenced code block, reports unclosed Mermaid fences, and labels the first-four cap. Nested list/blockquote fences and full Markdown document rendering are outside this implementation. Mermaid HTML labels, click actions, configuration/frontmatter, imported styles and embedded resources are refused explicitly. Complete literal source remains available through source tabs and Copy source.

All blob reads, source preparation, sniffing, container inspection, UTF-16 decoding, native image/PDF work and GPUI BGRA conversion run on the existing replaceable worker. Cancellation is checked between phases, sides and PDF pages. Native codec calls are synchronous bounded-input calls; cancellation cannot preempt an individual system decoder call. No decoder is a process-memory sandbox or hard wall-clock deadline.

The immutable cache remains limited to 32 entries / 128 MiB. It counts original captured byte buffers, literal source buffers, metadata strings, render pixels and existing patch/split/partial models. PDF page uploads retain only the prepared render buffer after converting each page; image comparisons retain RGBA, BGRA and bounded captured originals. UI `Arc`s and GPU textures may outlive cache eviction, so this is not a total process-memory cap. Mutable Working/Quick Open previews bypass the immutable cache. Errors/missing objects are not cached permanently.

GIF cache entries count every BGRA frame and timeline, plus retained first-frame
RGBA and original GIF bytes. Explicit playback uses native frame requests from
the painted comparison; paused or hidden previews have no animation timer loop.
Navigation snapshots pause the clock. Frame decoding checks cancellation and
time between bounded phases; a single codec call cannot be preempted.

Mesh previews independently cap source bytes at 32 MiB, decoded vertices at 300,000, triangles at 100,000, and FBX/OBJ nodes or 3MF object instances at 4,096. Rasterization allows at most 64 million candidate pixel samples across all four views, including overlapping geometry. Coordinates must be finite and bounded. The [ufbx supplied-memory loader](https://docs.rs/ufbx/0.11.3/ufbx/generated/struct.LoadOpts.html) has separate 96 MiB temporary/result allocator limits, progress cancellation, disabled external-file loading and a callback that refuses every file open; native references stay on the worker stack. [stl_io](https://docs.rs/stl_io/0.11.0/stl_io/) reads supplied bytes. Dedicated 3MF decoding validates a non-ZIP64 directory with at most 2,048 entries / 2 MiB directory data before decompression, caps the root relationship at 64 KiB and model XML at 16 MiB / 650,000 nodes, disables DTDs, and bounds component depth to 32. It follows the [3MF core build and transform model](https://github.com/3MFConsortium/spec_core/blob/master/3MF%20Core%20Specification.md) using in-memory ZIP parts only. Model textures, material paths and linked resources are never opened. These bounds are not a process-memory sandbox or hard wall-clock deadline; cancellation is cooperative between parse, geometry and raster phases.

General STEP tessellation was evaluated against the maintained [Truck STEP importer](https://github.com/ricosjp/truck/tree/master/truck-stepio) and its [meshing API](https://docs.rs/truck-meshalgo/0.4.0/truck_meshalgo/tessellation/trait.MeshableShape.html). That API exposes a tolerance rather than an allocation/cancellation budget, so this worker uses a finite faceted subset instead of unconstrained curved-surface tessellation. [STEP faceted-BREP entity definitions](https://www.steptools.com/docs/stp_aim/html/t_faceted_brep.html) describe the supported topology; this preview is not a CAD/manufacturing validation.

System preview is an explicit action. A serialized background handoff writes captured bytes into a newly created private temporary directory (0700) and read-only file (0400), with a fixed filename and an allowlisted/detected extension. Repository paths are never used as destinations. HTML/scripts and SVG source use text suffixes. macOS `/usr/bin/qlmanage -p` opens that captured copy. At most four viewers may be open through this process; each temporary directory is retained until its viewer exits and is then removed. Abrupt termination can leave a private OS temporary directory for OS cleanup; no repository or preference state is changed. Linux currently has no corresponding launcher and reports that limit explicitly.

CoreGraphics uses an in-memory CFData provider and page graphics only; it does not invoke PDF actions, JavaScript, launch links or URL loading. ImageIO uses in-memory source data and bounded thumbnail options. [Apple's ImageIO source APIs](https://developer.apple.com/documentation/imageio/cgimagesource) and [CoreGraphics page rendering](https://developer.apple.com/documentation/coregraphics/cgcontext/drawpdfpage(_:)) define these native primitives. Rich external application behavior is owned by system Quick Look, not counted as an in-app renderer.

## Behavioral evidence and native cases

`cargo test --locked -p gitturtle-preview` covers actual raster output for PNG/JPEG/WebP/GIF/BMP/TIFF/ICO, generated HEIC/AVIF fixtures, alpha and orientation, static PDF page order/pixels, page/output/source bounds, cancellation, corrupt data, SVG resource refusal, LFS pointer identity, strict UTF-16, WAV metadata, ZIP directory bounds and sfnt names. The HEIC/AVIF fixtures' generation provenance is in [their README](../crates/preview/tests/fixtures/README.md).

Worker tests exercise image content under an extensionless path, literal source under `.png`, captured SVG source, old/new renamed media bytes versus a different current working file, a missing object beside a readable metadata or rendered image side, stored image-named symlinks, shared Quick Open/Working media routing, local LFS retry and cache accounting. Captured-copy tests inspect exact bytes, safe path construction and filesystem permissions.

The coordinator's native acceptance cases are: BMP/TIFF/ICO; HEIC/AVIF; added and changed PDFs including page 8 of a 10-page document; different page counts on Before/After; corrupt/empty/over-budget input; source copying from SVG and decoded UTF-16; WAV/Office/archive/font metadata; opening a historical captured copy while the working file differs; Back/Projects/Quick Open return while a PDF read is pending; keyboard page controls, both densities, light/dark themes, minimum window width and enlarged text. Decoder tests establish pixels and bounds, not native layout, input latency or final installed build identity.
