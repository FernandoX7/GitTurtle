# Orca and a list row a search removes (2026-11-05)

## Decision and scope

- **Question.** In Keyboard Shortcuts, the first Down after typing a search that took away the row Orca last spoke followed Orca reading "GitTurtle", "Keyboard Shortcuts dialog …" and "Keyboard shortcuts by group List with 11 items" again before the row (QA-94, observation O1; FU9-B item 3). Which AT-SPI events and answers decide that, how do GTK4 and Qt answer for a removed row, and which answer keeps Orca to the row alone?
- **Finding.** At the next move Orca speaks the ancestors the new row does not share with the object it left. It speaks none when that object is dead or answers the same parent as the new row, and every ancestor up to the application when it can read no parent for the old object. A GTK4 row that leaves is dead to Orca; an AccessKit row is not, because libatspi rejects AccessKit's cache signals, and its parent cannot be read.
- **Recommendation (adopted).** The vendored `accesskit_atspi_common` keeps a selectable item that left the tree on the bus, defunct, with its `Accessible` interface only, answering the parent it had while that parent stays, for the 256 most recent such items. Orca then finds the shared list and speaks only the row Down moves to.
- **Outside this decision.** Moving to `accesskit_unix` 0.24.1, or backporting its cache-signal fix (below); VoiceOver on macOS, which uses `accesskit_macos`.

## How each toolkit's removed row reaches Orca

- **GTK4 (GDBus).** The removed row's proxy is disposed by its `(so)` `RemoveAccessible`, and the path answers "Object does not exist at path". Either error marks it dead (`handle_error`), and `_generate_ancestors` returns at 1141: Orca speaks only the new row. Orca's tests and fixes are written against this behaviour.
- **AccessKit 0.22.1 (zbus).** libatspi rejects the `so` `RemoveAccessible` and keeps the proxy. Uncached calls reach the bus and get "Unknown object", which Orca does not take as dead, and the cached name keeps `is_dead` false. `get_parent` fails, so there is no common ancestor, and Orca speaks frame, dialog and list. This happens whenever a search removes Orca's last-heard row before a move Orca hears, which depends on timing. Orca's 100 ms spam filter drops the selection changes of keys typed 60 ms apart, so its locus stays on a row the search later removes; QA-95 check 2d heard no preamble in one run.
- **Qt.** Destruction is reported only as `children-changed:remove`, so Orca learns of a gone object only from failed calls. Not exercised here.

## Compatibility and alternatives

- **Adopted: the removed row answers its last parent** (`vendor/accesskit_atspi_common`, `GITTURTLE-PATCH.md`). Orca's check at 1144 then sees the same list for both rows. The patch works with the libatspi and `accesskit_unix` GitTurtle ships today, needs no change to `accesskit_unix` or the app, and holds whether or not libatspi has the row's name cached: a failed name read makes the row dead, which also gives nothing. Its cost is up to 256 extra D-Bus objects per window, each with one interface, and a map lookup when a client reads a gone node's parent or a node is added. Removal is otherwise unchanged: `state-changed:defunct`, the cache's `RemoveAccessible`, the parent's `children-changed:remove`, and every other interface unregistered.
- **Backport `accesskit_unix` #819** (two lines in `emit_cache_signal`). This lets libatspi dispose removed proxies and stops the 257/318 warnings. It is not adopted here: it needs a new vendored crate, a root `[patch]` entry, lockfile and `vendor/AGENTS.md` changes outside this round's files. With a disposed proxy, the outcome depends on Orca marking it dead before the check at 1141. A cached name with no fresh failing call leaves it alive, and a disposed proxy's parent reads as none. So #819 alone needs its own Orca check, and once it lands the adopted patch is no longer reached.
- **Rejected:** a ghost row, which Orca would count as an item; a stable renamed node for the selection, which reverses FU8-F/QA92F's keyed rows and is spoken as a rename; the `TRANSIENT` state on rows to defeat libatspi's cache, which relies on libatspi internals and changes Orca's handling elsewhere; changing error texts, which come from zbus and `accesskit_unix`, not this crate.

- Open: the #819 backport or upgrade, with an Orca check of the same steps once libatspi accepts the cache signals.

Adopted in `fix(vendor): keep a removed list row answering its list on AT-SPI`. The QA-94 and stderr observations above are dated evidence of the build before the change; they do not validate it.
