# Orca and a list row a search removes (2026-11-05)

## Decision and scope

- **Question.** In Keyboard Shortcuts, the first Down after typing a search that took away the row Orca last spoke followed Orca reading "GitTurtle", "Keyboard Shortcuts dialog …" and "Keyboard shortcuts by group List with 11 items" again before the row (QA-94, observation O1; FU9-B item 3). Which AT-SPI events and answers decide that, how do GTK4 and Qt answer for a removed row, and which answer keeps Orca to the row alone?
- **Finding.** At the next move Orca speaks the ancestors the new row does not share with the object it left. It speaks none only when that object is alive and answers the same parent as the new row. It speaks every ancestor up to the application when it can read no parent for the old object, and the ancestors below the window when the old object is dead, since it then presents the move from the window (corrected below). An AccessKit row is not dead, because libatspi rejects AccessKit 0.22.1's cache signals, and its parent cannot be read.
- **Recommendation (adopted).** The vendored `accesskit_atspi_common` keeps a selectable item that left the tree on the bus, defunct, with its `Accessible` interface only, answering the parent it had while that parent stays, for the 256 most recent such items. Orca then finds the shared list and speaks only the row Down moves to. Since the follow-up below, the vendored `accesskit_unix` sends the cache signals libatspi accepts (AccessKit #819), and a kept item stays in libatspi's cache until it leaves the bus: once its list leaves the tree or is excluded, in the update that takes the item out or a later one, once it comes back excluded, or once 256 newer items push it out.
- **Outside this decision.** Moving to `accesskit_unix` 0.24.1; VoiceOver on macOS, which uses `accesskit_macos`.

## How each toolkit's removed row reaches Orca

- **GTK4 (GDBus).** The removed row's proxy is disposed by its `(so)` `RemoveAccessible`, and the path answers "Object does not exist at path". Either error marks it dead (`handle_error`). This note first concluded that `_generate_ancestors` then returns at 1141 and Orca speaks only the new row; the follow-up below corrects that: a dead locus is dropped before the move is presented, and Orca speaks the new row's ancestors below the window. Whether a GTK4 list view takes a filtered-out row out of the tree at all was not checked.
- **AccessKit 0.22.1 (zbus).** libatspi rejects the `so` `RemoveAccessible` and keeps the proxy. Uncached calls reach the bus and get "Unknown object", which Orca does not take as dead, and the cached name keeps `is_dead` false. `get_parent` fails, so there is no common ancestor, and Orca speaks frame, dialog and list. This happens whenever a search removes Orca's last-heard row before a move Orca hears, which depends on timing. Orca's 100 ms spam filter drops the selection changes of keys typed 60 ms apart, so its locus stays on a row the search later removes; QA-95 check 2d heard no preamble in one run.
- **Qt.** Destruction is reported only as `children-changed:remove`, so Orca learns of a gone object only from failed calls. Not exercised here.

## Compatibility and alternatives

- **Adopted: the removed row answers its last parent** (`vendor/accesskit_atspi_common`, `GITTURTLE-PATCH.md`). Orca's check at 1144 then sees the same list for both rows. The patch needs no change to the app. It holds while libatspi has the row's name cached, as QA-94's log shows it had; a failed name read would make the row dead, which gives the dialog and the list (follow-up below), not nothing as this note first said. Its cost is up to 256 extra D-Bus objects per window, each with one interface, and a map lookup when a client reads a gone node's parent or a node is added. Removal is otherwise unchanged: `state-changed:defunct`, the parent's `children-changed:remove`, and every other interface unregistered; since the follow-up the cache's `RemoveAccessible` waits until the item leaves the bus.
- **Backport `accesskit_unix` #819** (two lines in `emit_cache_signal`), adopted in the follow-up below. It lets libatspi dispose removed proxies and stops the 257/318 warnings. On its own it makes a removed row dead to Orca, which then reads the dialog and the list before the next row, and it would do the same to a row the adopted patch keeps, so a kept row's `RemoveAccessible` is withheld.
- **Rejected:** a ghost row, which Orca would count as an item; a stable renamed node for the selection, which reverses FU8-F/QA92F's keyed rows and is spoken as a rename; the `TRANSIENT` state on rows to defeat libatspi's cache, which relies on libatspi internals and changes Orca's handling elsewhere; changing error texts, which come from zbus and `accesskit_unix`, not this crate.

## Enforcement and acceptance

- Adapter: `adapter::tests::a_row_taken_out_of_its_list_answers_the_list_while_it_stays` and `rows_kept_as_removed_are_bounded_and_forgotten_on_return`, run with `scripts/vendor-crate-test.sh vendor/accesskit_atspi_common`, also check when a kept row is reported removed from the cache; `a_kept_row_leaves_the_bus_when_its_list_leaves_later` checks that a kept row leaves the bus and the cache once its list leaves the tree, or is hidden, in a later update, and `context::tests::a_row_kept_again_after_it_came_back_is_the_newest` and `a_row_taken_away_and_back_again_holds_one_place_in_the_queue` that the queue of kept rows holds each once, so a row taken away again is not pushed out first. `atspi::bus::tests::cache_signals_carry_the_signatures_libatspi_accepts`, run with `scripts/vendor-crate-test.sh vendor/accesskit_unix`, reads both cache signals' body signatures from the received bytes.
- App: `atspi_state_tests::Bus::heard_by_orca_from` models `_generate_ancestors`' quiet case, a prior object that is alive and answers the same parent, and libatspi disposing an object on the cache's `RemoveAccessible`, after which Orca takes it as dead and reads the ancestors below the window. `shortcuts::list_tests::the_first_down_after_a_search_took_the_heard_row_speaks_only_the_entry` and `command_palette::render_tests::a_search_that_takes_the_spoken_command_away_leaves_moves_bare` replay FU9-B's probe ("tab" 60 ms a key, then Down) and the palette's ("go").

## Follow-up: libatspi's cache signals (2026-11-05)

The vendored `accesskit_unix` 0.22.1 now carries #819, so libatspi takes the cache's `AddAccessible` and `RemoveAccessible` ([patch note](../../vendor/accesskit_unix/GITTURTLE-PATCH.md)). Reading libatspi and Orca again for what that changes corrected two claims above.

So #819 alone would not keep Orca quiet: the removed row would be disposed and dead, and Orca would read the dialog and the list before the row Down reaches. With the adopted patch unchanged, the row it keeps would be disposed the same way, since removal still sent `RemoveAccessible`. `accesskit_atspi_common` therefore withholds the cache's `RemoveAccessible` for an item it keeps and sends it when the item leaves the bus: beyond the bound, when its parent does not stay, in the update that takes the item out or any later one, or when it comes back excluded. libatspi keeps that item's proxy and cached name, Orca takes it as alive, and its parent, from libatspi's cache or from the adapter, is the list. libatspi still learns of every other object added and removed.

The decision was made by test, with the root fix in and the app model extended to dispose a proxy on the cache's `RemoveAccessible`. With the workaround reverted, both app tests heard "<context>": Keyboard Shortcuts before the row Down reached, the palette already as "go" took away the command it last spoke. With the workaround unchanged, both heard it the same way. With the withheld removal, both pass. The workaround stays, because these two tests need it.

## Outcome

Adopted in `fix(vendor): keep a removed list row answering its list on AT-SPI`, and with #819 in `fix(vendor): send AT-SPI cache signals with the signatures libatspi accepts`. The QA-94 and stderr observations above are dated evidence of the build before the change; they do not validate it.
