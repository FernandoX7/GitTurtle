# Opus 5.5 for every agent role, varied by effort

## Decision and scope

- Question: which model and effort each Claude Code role and each controller step uses. The owner decided on 2026-09-30 that every agent layer runs on Claude Opus 5.5 only and that roles differ only in effort.
- Recommendation: name the full ID `claude-opus-5-5` wherever a model is pinned, in role files and in long unattended runs, because the `opus` alias can move to a newer model. Delegated roles carry their effort in frontmatter: `Explore` `low`, `librarian` `medium`, the code, design and performance reviewers `high`. The controller defaults every step to `--model` and varies only effort: attempt 1 at `--effort`, attempt 2 at `--retry-effort`, attempt 3 onward on `implementer-hard` at `--hard-effort` (default: the retry effort), a docs/tooling-only task's first attempt at `--light-effort` (default `medium`), and the verifier and security reviewer at `--review-effort` (default `--effort`). The hard step defaults to the retry effort rather than `max` because the root guide forbids mandating maximum effort; an operator who wants it passes `--hard-effort max`, as the September 30 run command does. A docs/tooling retry runs at the higher of the retry and light efforts, so it never drops below its first attempt.
- `verifier` and `security-reviewer` pin neither model nor effort, so the flags the controller passes reach them; interactively they inherit the session's selection.
- Outside this decision: the child sessions' 300k auto-compaction window (`CLAUDE_CODE_AUTO_COMPACT_WINDOW` in `scripts/agent_loop/claude.py`) stays as a deliberate quality bound below the 1M context; the Codex adapter is unchanged. Turn caps are unchanged.

## Compatibility and alternatives

- The adapter's minimum Claude Code version (2.1.257) is unchanged. `scripts/agent_loop/guidance.py` at `b48c03d` already accepts `claude-*` model IDs and the five efforts (`AGENT_MODELS`, `AGENT_EFFORTS`).
- Keeping the `opus` alias was rejected: it can move to a newer model, and within the family it resolves to the parent session's exact model, so a delegated reviewer under an Opus 5 session would run on Opus 5.
- Keeping Fable 5.1 for the hard tail and Sonnet 5 for light tasks was superseded by the owner's decision. Naming `--hard-model` or `--light-model` still gives a step its own model, and `none` still disables a step.
- Pinning `effort: high` in the verifier and security-reviewer files was rejected. The controller always passes `--model` and `--effort` to those sessions, and the documented rule that frontmatter `effort` overrides the session effort could let a pin silently displace `--review-effort`.
- A run saved by an earlier controller resumes only through its own snapshot, because `Runner.__init__` refuses a live controller whose file digests differ; its original routing therefore needs no fallback here. `run` resolves every default once (`resolve_selection`), so a run this controller creates records a concrete model and effort for each step, and the adapter refuses an unresolved one.
- What would change this: a newer Opus release, which needs a new check before the ID is re-pinned; Claude Code documenting that `--agent` frontmatter yields to the flags, after which the two reviewer files could pin `high` for interactive delegation; or run evidence that a `--hard-effort max` session exhausts `--session-minutes`.

## Enforcement and acceptance

- Owners: `resolve_selection`, `SELECTION_OVERRIDES`, `Claude.__init__`, `Claude.configure_attempt`, `Claude.review_selection` and the session environment in `Claude.run` in `scripts/agent_loop/claude.py`; `CLAUDE_OPTIONS`, `make_adapter`, `create_run` and the `run` options in `scripts/agent_loop/runner.py`; `.claude/agents/*.md`.
- Controller tests: `test_attempt_routing_by_attempt_number_and_declared_profiles`, `test_selection_is_consumed_by_the_next_implementer_session` and `test_sessions_drop_variables_that_override_the_explicit_selection` in `scripts/agent_loop/test_claude_process.py`; `test_cli_defaults_route_every_step_to_the_base_model` in `scripts/agent_loop/test_claude_runner.py`.
- `python3 scripts/check-agent-guidance.py` validates each role's `model` and `effort` values.
- Remaining uncertainty: the precedence between a `--agent` role's frontmatter and `--model`/`--effort` is unprobed, and the `-p` JSON result reports the model used but not the effort, so the command line in each `<role>.process.json` and the `tasks.<id>.session` entry are the only records of effort. Stripping inherited variables does not reach an `env` block or a `maxEffortLevel` cap in user or managed settings, which child sessions still load; an operator with either set should clear it before a run.
