# GitHub platform facts for the CI clean-up (2026-11-18)

## Decision and scope

- **Question.** Which GitHub features and prices the CI clean-up's plan may rely on for a public repository owned by a User account. The user-visible outcome is a faster pull-request run that still runs the full suite before anything reaches `main`, at a cost that is known before it is proposed.
- **Finding, not yet a recommendation.** Every fact below was read on 2026-11-18 from GitHub's documentation, changelog, pricing pages or the named repository at a named commit. Three of them bound the plan:
  - A merge queue is not available to this repository while a User account owns it. It is available to any public repository owned by an organization, on any plan.
  - Larger runners are not available to a personal account on any plan, nor to an organization on GitHub Free. They need an organization or enterprise on GitHub Team or GitHub Enterprise Cloud, and a public repository pays for every minute on them.
  - Standard hosted runners stay free and unlimited for a public repository, the cache keeps its 10 GB at no cost, and at most 5 macOS jobs run at once across the whole account.
- **Outside this note.** Which test tools or third-party runners to use (the sibling note of the same date); the measured duration of any job; any change to the workflows. No setting was changed: every `gh api` call was a GET.

## Compatibility and alternatives

1. **Merge queue.** Not available here: a merge queue needs an organization-owned repository (public on any plan, private only on Enterprise Cloud). Where it is available, the workflow must also run on `merge_group`, and the one required check, `Quality gate`, must report on the queue's `gh-readonly-queue/main/...` commit or the entry fails at the timeout; a job can tell queue from pull request by the event name, which is how a narrower pull-request selection and a full queue selection would share one check (an inference from the contexts, not a documented recipe). This account can use what it already has: auto-merge with the strict required check, which GitHub describes as giving the queue's guarantee at the price of updating the branch and waiting again; a full selection started late would have to come from a `pull_request` or `pull_request_review` event, since a `workflow_dispatch` run cannot be relied on to satisfy a required check. Moving the repository to a free organization would unlock the queue and nothing else here: concurrency, cache and prices match Free, and larger runners need Team at $4 per user a month. A transfer keeps secrets, webhooks, deploy keys, issues and pull requests and redirects URLs and Git remotes, but the two owner-name conditions under `.github/` must change with it or cache saves and the release workflow's guard stop matching, and what happens to caches, protection rules and GitHub App installations is not established.
2. **Standard runners.** `ubuntu-24.04` and `ubuntu-24.04-arm` have 4 processors and 16 GB; `macos-15` and `macos-26` have 3 M1 processors and 7 GB; all are free and unlimited for a public repository. A personal account runs 20 jobs at once on Free or 40 on Pro, and 5 macOS jobs on either, counted across all of the account's repositories. A full run starts 4 macOS jobs, so two full runs at once already wait on macOS; no plan below Enterprise raises that 5, though GitHub Support can be asked to.
3. **Larger runners.** A personal account cannot use them on Free or Pro; an organization needs Team or Enterprise Cloud, and a public repository is billed for them. Per minute: Linux x64 $0.012, $0.022 and $0.042 for 4, 8 and 16 cores (16, 32, 64 GB); Linux arm64 $0.008, $0.014 and $0.026; macOS large $0.077 (12 Intel cores, 30 GB) and xlarge $0.102 (5 M2 cores, 14 GB). By arithmetic that is $2.52 an hour for 16-core x64, $1.56 for 16-core arm64 and $6.12 for macOS xlarge. For 2026: hosted prices fell by up to 39% on 2026-01-01 (in effect); the $0.002 a minute platform charge on self-hosted runners, announced 2025-12-16 for 2026-03-01, was postponed on 2025-12-17 and has no date; cache storage above 10 GB has been billable since 2025-11-20.
4. **The cache.** 10 GB a repository, entries unused for 7 days removed, and beyond the limit the least recently used go first. A repository administrator can buy more at $0.07 per GB a month (20 GB fully used would be $0.70) once a payment method is on file; whether Free without Pro qualifies is not established. A pull request restores from its own merge ref, its base branch and the default branch, and whatever it saves is visible only to re-runs of that pull request; the pages make no separate rule for a fork, so that is what a fork's pull request can save. `Swatinem/rust-cache` is at v2.9.3 (2026-10-20), one patch release ahead of the pin; `save-if: false` restores without saving, `cache-targets: false` keeps only the registry, `cache-bin` covers `~/.cargo/bin`, and `cache-all-crates` and `cache-workspace-crates` widen what is kept of `target`. This repository holds 8.48 of its 10 GB.
5. **Checkout and cancellation.** At v7.0.1, `filter: blob:none` with `fetch-depth: 0` fetches every commit and tree of every branch and tag and only the blobs the checkout needs; commands that read commits and trees, which is all `scripts/ci/changes.py` runs, work as in a full clone, while anything that reads old file contents fetches them from the remote on demand. With the default depth of 1 the filter saves nothing, since the one commit's blobs are fetched for the checkout anyway, and the history is still cut (the two sources read together; not measured). `cancel-in-progress` may be an expression, so it can cover any event; what it costs is the commit's check: a cancelled run of this workflow leaves a failed `Quality gate` on its commit. That is harmless on a superseded pull-request commit, where only the latest commit counts, but on `main` it would leave commits with a red gate, no full result and no cache save, and for `workflow_dispatch` it would cancel a run someone started by hand. `queue: max` is the documented way to keep every run and order them instead.

**Evidence that could change this.** GitHub extending the merge queue to personal accounts; a new date for the self-hosted platform charge; a change to the macOS concurrency of 5; the account's plan, once read.
