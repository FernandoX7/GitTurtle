# Review and publish rewritten history

Before an accepted native interactive rebase starts, GitTurtle durably records its canonical worktree, branch, exclusive base and original tip outside the repository. The serialized Git operation waits for that preference save; a failed capture prevents Git from starting. Records survive restart. They retain identities, not copies of Git objects; expired or missing objects are reported explicitly.

Open **Review rewritten branch series…** from the command palette, or **Review last rewritten series…** in Edit local commits. Local review resolves the captured branch's current tip, validates both available linear ranges, and displays Original and Rewritten commits. Where it has no series to show, the list's place says why as a designed empty state: the read under way; that no rebase started in GitTurtle captured one for this worktree, with **Edit local commits…** below it, which opens the rebase form as the menu's item does and is refused with the palette's reason for its own Edit local commits… while a write runs or a merge, rebase or cherry-pick is under way (where the branch menu leaves the item out), and says to return to the review's repository once that is no longer the one shown; or, under the title **Series not reviewable**, the load's error, such as a series past the bounds below. The same words are the list's accessible description and those of the actions that wait for a series. The first read holds the room of the state it most likely lands in, no capture with **Edit local commits…** below its line: where it lands there, the actions below the list never move as the review opens; where it lands on a failure, they move once, as it lands; and where it lists a series, they move as the series takes the list's place. **Refresh series** reads the capture again, the state keeping its height while it reads. An inspected commit's file box says "Reading changed files…" while its changed files are read, and the preview's box "Reading preview…" while a chosen file's preview is read, neither box moving or changing size; the text modes, Diagrams among them, keep their row for every preview, waiting for one with text, or for Diagrams one with Mermaid diagrams, and saying why: a notice's own words, as one past the text preview's limits says, or a failed read's error, which the preview's box says in the preview's place; and where the preview lies below the body's view, as at 18 pt in a 461 × 490 window, the chosen file's row says "Reading…" at its end, in its accessible description too, and nothing scrolls: a press never moves what was pressed. A click on a preview's open control that opens nothing answers on a line beneath it, and where that line lands outside the body's view, as beneath a control scrolled to the view's foot, the body scrolls the least that shows it whole, focus staying on the control. The review's body takes the room the dialog's height cap leaves it below the title and above **Back to repository**, as the dialog lays them out, and scrolls the rest; an inspector fills that room. The series list shows the whole rows that room holds beside the rest of the body, at least one and at most six, never a row cut at its foot: it scrolls by whole rows, Up and Down scrolling it the least that keeps the selected row whole, as does a change that moves its rows with no key, in the frame it lands: a resize or a text size that changes how many rows it shows, a display scale that changes their snapped height, and a new series, from Refresh series or a destination check that found the remote changed, which selects its first row; and its scrollbar cues the rows past its edge. **Review messages** shows exact original/new messages. Select either side's file inspector for its changed paths and captured patch/source/image/document previews; Return on a commit row inspects its rewritten files, or its original files where the rewrite dropped it, as Return on a History commit loads its files, and leaves the review open. An inspector opens with focus on **Back to series**; it and Escape retain the selected correspondence and series scroll; Escape on the series, like **Back to repository**, closes the review and leaves the underlying repository context intact. Closing cancels outstanding reads, and late replies cannot reopen the inspector.

## Correspondence and bounds

Git documents [range-diff output as human-readable, unstable porcelain](https://git-scm.com/docs/git-range-diff). GitTurtle does not parse it. Matching first uses identical commit IDs, then unique [stable patch fingerprints](https://git-scm.com/docs/git-patch-id). Patch fingerprints ignore whitespace and line numbers, so a separate exact diff digest (excluding only index-object headers), exact message and author name/email determine whether a paired entry is labelled changed. Unique remaining subjects can identify only a **Possible match**, visibly marked for inspection. Reordered pairs are detected by changes in relative order. Repeated/ambiguous, combined and unmatched commits remain labelled; empty patches never create a fingerprint match. This is conservative correspondence, not Git range-diff's similarity algorithm.

Review accepts at most 100 commits per series. Each of its reads keeps at most 4 MiB of Git's output, so a commit whose patch is larger, as a large binary file's is, cannot be reviewed, and the patches and messages of a whole series stay within 32 MiB in all; both bounds hold (`WRITE_OUTPUT_LIMIT` and `SERIES_BUDGET` in `crates/git-core`). A series past either is refused as too large to review here, naming `git range-diff`, rather than as an unavailable series. Root, merge-preserving, unrelated-base and larger ranges require Git's tools. Process cancellation applies. All reads use the passive Git policy: no repository writes, configured diff helpers, text conversion, network access or lazy object fetch. Commit selection requests only changed-file metadata; explicit file activation reuses the bounded preview worker and literal-source editors.

## Separate publication

Completing a local rebase never publishes it. Enter one named remote and branch, then explicitly **Check publication destination…**. This network inspection checks that remote's effective single push URL, the named remote branch OID and the reviewed local branch tip. Authentication reuses the ordinary configured helpers, SSH/agent and transient prompt/cancel path.

The publication review displays the destination, complete expected remote ID, complete reviewed replacement ID and history-replacement consequence. **Publish with exact lease** submits one typed operation to the existing serialized executor. The command revalidates the local branch and remote URL, then uses `--force-with-lease=<ref>:<expected-oid>` with one explicit source/destination refspec. Its destination argument pins the captured URL so a concurrent edit to the named remote cannot substitute another push URL. Git's pre-push hook receives that URL as the destination argument and can refuse publication. Git's [explicit lease semantics](https://git-scm.com/docs/git-push) protect against an intervening remote update. No unrestricted force fallback, automatic retry, mirror, recursive submodule push or extra tag push is used. Ordinary Push keeps its non-force behavior; hooks, authentication and server branch protections remain active.

After remote movement, a new explicit destination check can load the newly observed remote series when its objects are already local. The UI clears publication approval and requires reviewing those rows and checking the destination again before preparing a fresh lease. Missing objects require an explicit ordinary Fetch first; unrelated/merge history remains unsupported rather than guessed. An explicit check that finds the remote already at the reviewed new tip reports completion without another push. This also provides a deliberate check after an uncertain outcome.

Failures, cancellation and interrupted replies can leave a remote update applied. The operation reports this uncertainty and never replays the push. A new review is required; merely reopening the app or returning focus performs no network inspection.

## Validation

`cargo test --locked -p gitturtle-core --test rewrite_review` uses disposable local remotes for exact-lease success, reorder/drop, changed messages/whitespace, possible/added/empty correspondence, missing objects, local/remote/URL movement, rejection, cancellation and cancellation after the remote updated. It also verifies the separate fresh-review path after explicit Fetch and completion detection. Unit coverage refuses invented pairing for repeated patches and empty commits. [Native fixture instructions](recovery-rewrite-native-cases.md) separate process/core evidence from native interaction and installed-build evidence. Hosted destinations require their own authorization and are not established by these local fixtures.
