# Disposable profiles and palette native cases

The coordinator owns native app state backup/restore, UI interaction and installed-build evidence. Generate isolated repositories and keys with:

```sh
python3 scripts/create-profile-fixtures.py --output /tmp/gitturtle-profile-native-FRESH
```

The script refuses existing content and writes `fixtures.json` inside its disposable output. It creates unsigned, Personal-signed and Work-signed repositories, a shared linked worktree and a private linked worktree. It creates two new unencrypted Ed25519 fixture keys outside the repositories, without using the user's agent, keyring or global Git configuration. Each repository has a commit hook and an unrelated configuration sentinel. Never paste private-key bytes into a profile or conversation.

1. Open `unsigned`. Header menu: inspect full hover/padding and caret, use keyboard Up/Down/Return/Escape. Create a profile named **QA Unsigned** using its current identity; cancel an edited name and reopen to confirm the unsaved form remains recoverable. Saving a definition must leave `.git/config` unchanged.
2. Open `personal`; create **QA Personal** and enable **Include the existing signing configuration**. The displayed reference should be the generated Personal key, SSH, commit signing and tag signing enabled. Repeat in `work` as **QA Work**, capturing the different key. No application occurs merely from saving a definition or reopening another repository.
3. Return to `personal`. Choose **QA Work**, verify the review's exact worktree/configuration path and shared-scope explanation, then Apply. Stage the prepared `identity.txt` edit and commit through the existing composer. Verify actual author/committer, the configured hook, unchanged `custom.profileFixture`, and `git verify-commit HEAD`. Create an annotated tag whose annotation has no final newline; verify it with `git verify-tag TAG` and inspect its tagger. The selected Work key must be the actual signer.
4. Apply **QA Personal** back to the same repository and repeat an explicit small commit/tag. Verify both signatures. Rename the selected fixture private-key file temporarily and attempt another signed commit/tag: errors must preserve HEAD/index, retain signing and never create unsigned fallback objects. Restore the fixture key path afterward. This remains disposable local signing evidence, not hardware/Keychain/provider evidence.
5. Apply **QA Personal** to `linked-shared`: its review discloses shared repository effects, and `unsigned` inherits the new identity. Apply **QA Personal** to `linked-private`: only private `config.worktree` changes, and the main `work` repository retains its Work identity. No application enables worktree-specific configuration implicitly.
6. Edit a saved definition or explicitly change the disposable repository's `user.email` with Git, then Refresh. The header must show **differs** against the saved assignment; reopening must not overwrite the external edit. Delete the definition through its review: repository configuration, keys and work remain intact. Inspect unchanged global configuration only with non-secret metadata/checksums if desired.
7. Restart the app and verify saved definitions/assignments survive. In a disposable app-state copy, a malformed/unknown `profiles.json` or temporarily unwritable storage must show an error and preserve the original bytes. Editing text remains recoverable after a failed save. Retry does not replay an already applied Git operation. Return to the coordinator's backed-up genuine app state after these tests.
8. Palette: Command-Shift-P, immediate typing **profiles**, Up/Down/Return into the profile manager, Escape back to the original editor/list focus; Command-P still opens Quick Open. Test **themes**, **blame**, **worktrees**, **reflog**, **rewrite**, an unmatched query, and disabled commands from Projects or during a Git operation. Confirm navigating shortcuts under the open palette do not change hidden pages. Inspect light/dark themes, both densities, enlarged interface text, minimum size, visible hover and selection. A selected-file inspection command must refuse a changed file target until the palette is reopened.

Record actual observations, source/build identity and screenshots in the milestone record. Unit/core fixtures alone do not complete these native cases.
