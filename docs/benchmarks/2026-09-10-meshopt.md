# Meshopt GLB coverage and release measurements — September 10, 2026

These results measure actual captured-byte decoding and CPU rendering. They do
not measure native event-to-display latency, GPU completion, or process peak
memory. [Native interaction/package evidence](../meshopt-preview-validation.md)
is recorded separately.

## Current authorized corpus coverage

The current passive inventory contains 1,379 regular GLBs totaling 180,048,188
bytes, including 1,255 with meshopt buffer views. Every raw input was captured and
hashed outside GitTurtle. Current source GLB hashes and source HEAD matched the
initial inventory after capture/reference work. No source-repository writes,
external resource loads, Git/LFS fetches, filters or conversion operations were
performed. Original source filenames, captured bytes and screenshots remain
private; published records use ordinal labels and reproducibility hashes.

The meshopt subset now has 1,130 actual decode/render successes out of 1,255;
78 skin and 47 empty-scene cases remain refused. Those underlying limitations
were previously masked by the unsupported-compression refusal. Every successful
final decode also completed all three measured raster variants. This is current
asset coverage, not a claim of general animated/skinned glTF support.

The input inventory contains ATTRIBUTES and TRIANGLES streams, with NONE,
OCTAHEDRAL, QUATERNION and EXPONENTIAL filters. Some filtered streams contain
omitted normal/animation data. Their presence is not evidence of animation
playback or filter use by retained geometry. The procedural and inline decoder
fixtures separately exercise the supported compression modes/filter contracts.

## Independent geometry expectations

The [reference summary](2026-09-10-meshopt/reference-summary.json) compares 17
renderable selections representing 14 distinct captured input hashes. It covers
three real private historical pairs, private 33-node/19-mesh and 14-node models,
quantized geometry, both authored arches, the CC0 Avocado derivative, and the
compressed/uncompressed dense torus. Current captures overlap three latest
historical sides; the count of distinct inputs makes that duplication explicit.
Two selected empty scenes are refused by both implementations.

The pinned official meshoptimizer JavaScript/WASM decoder and a separate
JavaScript accessor/scene-transform interpreter produce complete expanded f64
triangles. Every coordinate is compared against the production Rust export,
including transformed placement and meter-to-millimeter axis conversion.
Triangle counts match exactly; the largest absolute coordinate difference is
`4.55e-13` mm and the largest bound-coordinate difference is `5.69e-14` mm.
Several inputs match byte-for-byte. The reference additionally decodes and hashes
all embedded compressed views, including filtered normal/animation streams;
those streams do not become evaluated animation. The meshopt triangle codec may
cyclically rotate vertices while preserving triangle identity and winding; the
fixture encoder checks this against original index data.

[Fixture provenance and reproduction](../../crates/preview/tests/fixtures/models/glb/README.md#meshopt-fixtures-and-independent-codec-reference)
records licenses, immutable upstream URLs, runtime/module hashes and commands.
The reference script is validation tooling for known static fixtures, not a
second production validator.

(Mac16,5), 16 logical CPUs, 128 GiB memory. macOS 26.6.2 (25G83), Rust 1.98.0.
The [manifest](2026-09-10-meshopt/timing-manifest.json) records executable/input/raw
sample hashes, fixture order, timestamps, retained-scene accounting and all
p50/p95/p99/max values. Source compilation had finished before this series.
Ordinary desktop background load remained: observed CPU 27.99% user, 14.40%
system and 57.60% idle; load averages 22.38/22.41/17.15. Native layout inspection
could overlap. No CPU isolation or thermal control was applied.

Each fixture has one preserved first attempt, three preserved warmups and 100
measured samples. Input bytes are read once and stay resident. Every row decodes
a fresh scene without an application cache and renders fresh 360-solid,
720-solid and 720-wireframe images from that scene. File I/O, camera fitting,
output destruction, app scheduling, GPUI, GPU upload and OS presentation are
excluded. All outliers remain; percentiles use nearest rank. The first attempt
is not a cold-filesystem benchmark. Scene retained-byte accounting is not peak
process memory.

## Raster refusal remains independent

The publishable `raster-limit.glb` fixture has 1,000 coincident compressed
triangles: only 3,172 input bytes and 72,099 retained scene bytes. Geometry
decoding succeeds. Its fitted 720-solid render explicitly refuses the independent
64-million raster-sample budget; 360-solid and 720-wireframe complete. This
checks that a small compressed asset cannot imply small raster work. The
disposable History fixture pairs a valid Before with the raster-heavy After;
actual native behavior is recorded separately.
The generator records this case separately from malformed decoding.

Reproduce the actual outcome with:

```sh
cargo build --release --locked -p gitturtle-preview --example probe_models --example bench_model
python3 scripts/create-meshopt-preview-fixtures.py /tmp/gitturtle-meshopt-fixture --upstream-js /tmp/meshoptimizer-js > /tmp/gitturtle-meshopt-manifest.json
target/release/examples/probe_models /tmp/gitturtle-meshopt-fixture/raster-limit.glb
target/release/examples/bench_model /tmp/gitturtle-meshopt-fixture/dense-torus.glb 100 3 > /tmp/gitturtle-meshopt-torus.tsv
```

The fixture tooling requires the pinned upstream modules described in provenance;
it never downloads them or reads resources referenced by GLB content. Keep output
manifests, timings and private evidence outside watched fixture repositories.
