# Parallel work and reflog recovery

The current-branch menu opens **Worktrees…** and **Local reflog & recovery…**. Right-click a registered worktree in the navigator for **Worktree actions…**, **Remove worktree…**, or **Force remove worktree…**; Shift+F10 on a focused worktree opens its actions. These actions keep the current repository open, so selecting a removal target does not make it the current worktree. The manager selects the captured row and clears any retained filter or Create tab; a missing or changed target requires a fresh review. A removable target opens a confirmation with its folder, branch, and commit. A protected target shows its refusal reason in the manager. The manager offers the same **Remove worktree…** and **Force remove worktree…** buttons for the selected worktree.

These native dialogs retain the repository browsing context. Their metadata, status, and commit reads run on separate serial readers; closing, cancelling, or replacing a read cancels an active Git subprocess. Switching between Manage and Create also cancels a pending worktree review. Accepted mutations use the application's existing serialized operation executor and are never replayed automatically.

## Worktrees

Create from an available local branch, or name a new branch starting at a local branch, tag, or commit. The native folder picker retains the actual parent path, including filename bytes; enter one new folder name. Review the resolved commit, branch, and absolute destination before creation. Destinations must be absent and their parent must exist. Creation preserves Git checkout hooks and filters. Git initializes private configuration according to its worktree semantics; later per-worktree configuration and GitTurtle commit drafts remain independently scoped.

Selecting a worktree reads its current branch, HEAD, folder availability, dirty/untracked count, and ignored content. The manager reads that captured target again when Remove is chosen, so changes made while its details were open appear before confirmation. Status is loaded for one selected worktree rather than scanning every folder on list refresh. Search filters the full loaded list; the native dialog renders at most 100 matches at a time. Creation offers GitTurtle, Finder/file-manager, and configured-editor handoff; these actions also remain available in the manager.

Removal reviews one captured linked-worktree identity. GitTurtle refuses the main worktree, the currently open worktree, locked or missing worktrees, active integration/conflict state, changed/untracked files, and ignored files. Private Git locks, active bisect/sequencer state, and assume-unchanged or skip-worktree index entries also block removal. These flags can hide modified tracked bytes even from Git's own removal check; sparse worktrees require review with Git. Git's refusal for initialized submodules remains in force. It rechecks identity and content immediately before invoking ordinary `git worktree remove`, with no force. The branch remains available.

**Force remove worktree…** is a separate explicit action for a worktree whose content you want to discard. Its confirmation keeps the target and irreversible-loss warning visible above a scrolling review. **Will delete** lists changed or untracked files and ignored files (up to twelve of each, with remaining counts), unfinished merge, rebase, cherry-pick, bisect or sequencer state, and the private worktree metadata. **Will keep** identifies the branch and its commit, shared repository data and other worktrees. A detached commit is explicitly identified as needing a branch or tag for lasting recovery. Cancel preserves the worktree; the distinct destructive confirmation invokes `git worktree remove --force` once. Uncommitted content is not recoverable from Git.

Both removal actions refuse main, current, locked or missing worktrees, held index/HEAD/configuration locks, and assume-unchanged or skip-worktree entries that could hide local changes. Force removal also protects initialized and retained submodule repositories. A bounded filesystem inspection detects nested `.git` directories and bare repository/object-store signatures independently of Git status, including in tracked and ignored folders. It does not follow symbolic links. The manager displays the applicable protection and recovery guidance beside disabled removal actions; an unavailable force action is never suggested as the way forward.

The captured review includes the filesystem inventory and actual bytes of changed, untracked and ignored files. Edits, replacements and new paths after review require a fresh confirmation, including changes beyond the displayed lists. Unreadable or special entries, concurrent changes and exhausted inspection limits block removal rather than accepting a partial review. Worktree details remain available so the affected content can be inspected or moved outside the worktree. The [core service notes](../crates/git-core/README.md) document the inspection budgets and cooperative cancellation boundary.

Missing-folder repair and metadata pruning remain unavailable. Success requires that the folder, captured private Git directory and registration are absent; the branch is retained. A failed command or unverifiable cleanup reports an uncertain result and requires inspection before another explicit attempt. GitTurtle does not retry or clean up remaining content. Git owns removal of the linked folder and its private administrative files, following the [Git worktree command's cleanup semantics](https://git-scm.com/docs/git-worktree).

## Reflog

The browser initially reads this worktree's private `HEAD` log. Enter a local branch name or exact `refs/heads/…` reference to inspect its shared log. Git reflog entries include reference movements made by other tools, but they expire and may outlive their commit objects. The browser is bounded to the newest 1,000 records within a 4 MiB tail and explicitly identifies a truncated or empty result. Raw reflog records remain visible when their objects have disappeared. Symlinked reflog files/directories are refused.

Select an entry to inspect its available commit, message, timestamp, parent count, and changed paths against the first parent (or empty tree for a root). At most 100 changed paths are shown. Copying its full object ID is explicit. **Review recovery branch…** prepares a new local branch pointing to the selected commit. Confirmation revalidates the log snapshot, commit, repository directories, and unused branch name. It does not checkout, reset, alter the index, change working files, contact a remote, or stop an active Git operation. Changed or expired entries require a refreshed review. Missing objects cannot be recreated from a reflog entry alone.

## Evidence

`cargo test --locked -p gitturtle-core --test worktrees_reflog` passed six behavioral fixtures covering source index/work preservation; independent worktree configuration; existing/new branch creation; occupied branches/destinations; stale refs; dirty, ignored, locked, main and missing worktree refusal; branch retention after removal; a failed checkout hook with observed retained branch and no cleanup/retry; recovery with staged and unstaged work; stale reflog rejection; bounded missing-object logs; private/shared reflogs; and symlink refusal.

`cargo test --locked -p gitturtle-core cancelling_inspection --lib` passed the active-process cancellation and scope-restoration regression. `cargo check --locked -p gitturtle` passed with the registered dialogs. These are backend/build checks; actual native interaction and final installed-package evidence belong to the milestone's combined verification record.

The [release backend measurements](benchmarks/review-bench.md) cover worktree listing/selected details, a 1,000-entry HEAD reflog, and missing-LFS plan preparation with raw samples and read-only fixture fingerprints. They are absolute backend observations, not a before/after speed improvement claim.
