Build under test: gitturtle-301d82a, GitTurtle 0.1.0, release, x86_64-unknown-linux-gnu,
rustc 1.98.0 (88d9e12ae 2026-08-18), source_revision 301d82af8d1cd06fa8a1d7ded1892e89ffd1a4e0,
source_tree clean, sha256 84d80a41545fe6e40318cb5cedb773f187eaa28c60756523ff4e2d858f39acd2.
Fixture repository: theme-fixture at 52f471a1137c617fd8e36db2e6251a18f58c23eb, clean before and
after every launch. Command per launch: `gitturtle-301d82a <fixture>` with DISPLAY=:1,
WAYLAND_DISPLAY unset, GPUI_X11_SCALE_FACTOR=1, an absolute XDG_CONFIG_HOME created and seeded
for that launch alone, HOME redirected into the run directory (so the save dialog's start folder
and every written document stay there), and no network. Windows 1000x680 (the minimum) and
1440x900. The app is driven from the keyboard; the pointer only wheels the Settings page to the
Your themes card and, in the 32-theme capture, rests on a disabled button.

The file dialogs are not the app's own: on this desktop (GNOME 46, mutter, Xwayland :1)
prompt_for_new_path and prompt_for_paths reach a real xdg-desktop-portal-gnome dialog, which is a
Wayland client of the compositor. python-xlib cannot see or photograph it and XTest input never
arrives there; the dialogs are therefore recorded through AT-SPI and the portal's D-Bus traffic,
and driven with compositor input. There is no capture of a dialog in this set — the app's own
window is what these PNGs show.

Every capture here uses short strings, so none of them depends on how a long document string is
rendered: the unknown key is "author", the bad colour "rebeccapurple", the unknown base
"aurora-9", the missing token "hunk", and the over-64-KiB document is refused on size before it is
parsed, so its capture shows only the constant sentence. The two export captures quote the
absolute path the app wrote, so reproducing them needs the same run directory.
