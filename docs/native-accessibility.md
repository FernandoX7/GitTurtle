# Native accessibility

GitTurtle’s current milestone includes VoiceOver, ordinary keyboard navigation and the available macOS display settings. Earlier dated milestone exclusions do not limit current work. Implementation and automated checks below are separate from the coordinator’s build-specific native evidence.

## Native semantics

The app uses the pinned GPUI Kit and AccessKit bridge. Custom controls need explicit stable IDs, roles and readable labels; drawing text is insufficient. A text field's placeholder is never its name: the kit names an unlabelled field after the placeholder it shows, which a narrow field shortens to whole words (the Changes and History filters read "Filter" at 18 pt in a 461 px window), so every field carries its whole name, such as "Filter working paths", "Filter changed paths", History's "Search repository history" and the navigation's "Filter branches and worktrees". In this toolkit version, anonymous text and `StyledText` do not create accessible nodes. Rendered Markdown therefore provides bounded readable prose, heading levels, code text, linearized table rows, image descriptions and separate Before/After documents. Exact Source remains available, and link buttons are separately reachable. PDF and model controls name their side, page or camera action; checked state is reserved for actual toggles.

A label's text is its value: AccessKit's adapters name a `Role::Label` node by its value and never by its label property (AT-SPI and Windows announce the value as the name; macOS reports it as the static text's `AXValue`), as GPUI's own text element writes it. Every empty and edge state's line, and the title and explanation that loading and failures keep, was a label named only by its label property, so AT-SPI reached "No remote", the detached HEAD's line, "No upstream", no commits yet, a clean working tree, the empty Tags and Stashes lists and the GitHub panel without a GitHub remote as labels without a name. Each is static text (`native_accessibility::static_text`) read by its whole line, the caption included where the drawn line has given it up, with what its tooltip explains as its description, at the place the window draws it among the controls around it. `native_accessibility::state_tests` walks those states in repositories with no remote, no upstream, a detached HEAD and no commits, and in Changes, Tags, Stashes and the GitHub panel, at 13 pt in a 1,280 × 800 window and 18 pt in a 461 × 490 one (461 × 980 for the GitHub panel, whose list lies below its fold in the short one), through AccessKit's filter and, on Linux, the AT-SPI adapter, and checks each line's role, name and order, and that a line beneath an open dialog is out of reach. Every other label is static text too: the Tags dialog's, Blame's, the ignore form's and the other dialogs' lines through `native_accessibility::text`, the key hints of the command palette, Quick Open and Keyboard Shortcuts (`shortcuts::dialog_help`), Quick Open's note and empty and failure lines, the Projects page's breadcrumb ("GitTurtle", "Projects"), its "You can also open…" line and its feature notes, and lines styled in place, such as the authentication prompt, the operation consequences, the About version, the repository heading and the working filter's notes (which had no name at all), through `static_text`; Markdown rows and model details, whose role is chosen per row, write their text as the value on the same node. A dialog's styled title (`native_accessibility::dialog_title`) is a label with its text as its value alone, from which the toolkit's dialog also takes its name, reading a `Stateful<Div>` title as the adapters read a label ([base patch](../vendor/gpui-base/GITTURTLE-PATCH.md)); it kept its text as its label property too, which macOS reports as the title's `AXTitle` beside its `AXValue`, so VoiceOver could read it twice (VoiceOver has not been checked). `state_tests::every_label_of_these_screens_is_named` walks History, Blame, Changes with a filter that matches nothing, Tags and the ignore form, and `dialog_hints_and_the_projects_page_are_read_by_their_lines` the command palette, Quick Open, Keyboard Shortcuts and Projects, and each fails on a label written without a name or a line of theirs not written as static text. Keyboard Shortcuts' count is a polite status named by the line it draws, "61 shortcuts · Ctrl, Alt and Shift", where it was named "61 matching shortcuts"; its noun agrees with the count, "1 shortcut" after a search that leaves one, where both read "1 shortcuts". The toolkit's own synthetic title, for a dialog whose title is plain text, such as the command palette's, was a label named only by its label property, which AT-SPI reached without a name; the [base patch](../vendor/gpui-base/GITTURTLE-PATCH.md) writes its text as its value alone, so macOS reports no `AXTitle` beside its `AXValue` (`dialog_tests::a_plain_text_dialog_title_is_read_by_its_text`). Orca has not been checked.

History commits, changed files and working entries expose selected state, with exactly one current row reported as the active descendant of the focused list. Commit labels include subject, author, short identity and merge-parent count. Working multiselection retains all selected states while only the keyboard cursor owns active focus. The navigator is a tree with nesting and folder expansion state; Up/Down/Home/End skip section headings, Right expands or enters a folder, Left collapses or returns to its parent, Enter/Space activates, and Shift-F10, or on Linux the Menu key, opens the cursor row's menu below it, the one a right-click opens: a branch's name and Branch actions…, a worktree's path, actions and removals (Shift-F10 once skipped the menu for the branch's or worktree's dialog, and the Menu key did nothing in either tree). Scope activation remains explicit. In History's commit list, its changed-file list and the Working Changes list, Shift-F10, or on Linux the Menu key, opens the cursor row's menu below the row, the one a right-click opens: a commit's Revert and Cherry-pick, with Amend and Undo for HEAD (the commit list had no keyboard menu), and a Working Changes row too narrow for its Stage or Unstage control keeps that action from the keyboard; the menu's first Down reaches its first action and Escape returns focus to the list or tree (`native_accessibility::KeyboardMenu`, shared by every tree and list that opens a row's menu). The optional project list pane is a second tree with the same bindings and one tab stop: group rows report expanded state and project counts, the open project reports selected state, the cursor row is the active descendant, Shift-F10, or on Linux the Menu key, opens the row's menu beside it and returns focus to the tree when it closes, and a refused edit or failed save is an assertive alert inside the pane. Warm repository tabs retain the cursor.

A container whose children can leave view is a node that clips them, with bounds that are the part of it the window draws (`native_accessibility::clips_children`): History's horizontal scroller, commit and changed-file lists, the Working inspector's file list, scrolling selection row and composer fields, the navigator and project list trees, the repository tab strip, Settings' page and the custom theme editor's columns, the Projects hub's body, the inspector's revision details, File History's header, revision list, failure notice and footer, Blame's lines and line history, and the GitHub panel with its pull request list, changed-file and patch lists, conversations, collected comments, saved drafts and previous attempts. In dialogs it covers the Reflog's content, entry list and changed-file list, every list cued by `tags::ScrollCue` (the branch chooser, remote manager, tags and tag push remotes), Activity's content and entries, the rebase plan, sequence and message, the comparison form, Quick Open's form and results, the command palette's and Keyboard Shortcuts' results, the profile manager and form, the worktree manager with its worktree and branch lists, the mainline parent choice, the stash and stash-file lists, the local workspace library, the rewritten-series body and list, the LFS download review, About's details, and the discard and force-removal reviews' scrolling explanations. A list the window renders only in part (a `uniform_list`) clips at the role-bearing list box or tree that holds its rows, so the rows stay that list's own children. Left out: scrolling text with no nodes inside (operation consequences, error and confirmation text), lists without a node of their own whose rows lie in a clipping page (Your themes, saved recovery drafts, a rewritten commit's files, recent projects), and documents read as a whole (rendered Markdown and PDF, model details, rich previews and the inspector's commit message), whose off-screen text a screen reader's continuous reading still needs while GPUI offers no scroll into view for the neighbour AccessKit keeps. GPUI gives each node its layout bounds and never marks clipping, so AT-SPI reported controls the window does not draw `visible` and `showing`, such as Reflog entries below the list and below the dialog, and a commit list running past the window's edge; a screen reader could find and activate them. AccessKit's filter leaves out a child wholly outside its clipping parent, except the first one past each edge, which it keeps for an assistive technology to move into, and a focused node wherever it lies. That neighbour is intended, not a leak: the Reflog's entry list at 13 pt in a 640 × 680 window draws about six entries, to HEAD@{5} on the native fixture, and AT-SPI also reaches HEAD@{6} past its fold, so a screen reader can move on and scroll the list, while the list's scrollbar cues the same rest to sighted users (`reflog::tests::assistive_technology_reaches_only_the_entries_drawn` keeps it). Every dialog (the Reflog, the rebase form, the GitHub panel, the command palette, Quick Open, Keyboard Shortcuts, the discard and worktree-removal reviews, the Settings dialogs and the rest) opens through the kit's one dialog layer, which the window draws beside the page rather than in it, and the page, everything from the tab strip to the bottom strip, is a node that is hidden while any dialog is open (`native_accessibility::beneath_modal`). ## Toolkit patch

The pinned `gpui-base` Button previously prevented disabled activation but omitted AccessKit’s disabled flag. The focused [vendored patch](../vendor/gpui-base/GITTURTLE-PATCH.md) adds that flag while delegating the original rendering and interaction behavior, retaining Apache-2.0 notices and dependency versions. The actual rendered-node regression checks role, label, disabled metadata, absence of disabled click actions and selected/unselected Tab metadata. Tab roles map existing selected presentation to native selected state; ordinary buttons do not acquire selected or pressed semantics. The focus-trap wrapper also forwards its accessible role, metadata and synthetic children, and marks Dialog/AlertDialog roles modal; a dialog's kind decides which of the two it is. Its previous omission could leave the focused dialog host absent from the tree and produce window-level fallback focus. A wrapped-node regression covers named dialogs and generic groups. Native traversal must still verify containment, restored focus and discovery of unavailable controls. On Linux the pinned AccessKit AT-SPI adapter, `accesskit_atspi_common` 0.19.1, reported every disabled Button `enabled` and `sensitive`, and a disabled Switch, CheckBox or text input `read-only` ([September 30](validation.md#september-30-tab-leaves-a-focused-button-that-turns-disabled)). A [vendored backport](../vendor/accesskit_atspi_common/GITTURTLE-PATCH.md) of the upstream fix reports none of these on a disabled control, and enabled controls keep `enabled` and `sensitive`. The Linux-only `native_accessibility::atspi_state_tests` checks the adapter's state sets, and [October 1](validation.md#october-1-disabled-buttons-report-disabled-to-at-spi) records the native AT-SPI read. The kit's Checkbox and Switch do not set AccessKit's disabled flag yet, so a disabled check box or switch still reads as enabled on Linux. VoiceOver on macOS and Orca speech are not covered.

Persistent presentation selection and semantic toggle state are separate toolkit properties. Apply `.toggled` only to real switches or modes, and explicit tab/selected roles for repository tabs. An action such as Fit or Reset must not be announced as an unchecked toggle merely because it is unselected visually.

Menus follow the same rule. An item built with `PopupMenuItem::checked`, or through the kit's `menu_with_check` builders, is a check menu item (`Role::MenuItemCheckBox`) whose toggled state follows its tick; every other item stays a plain menu item, so a menu that ticks a choice marks each of its choices checkable (the branch chooser's other branches take `.checked(false)`), and a command beside them, such as the review Options menu's More context and Reset review, stays plain. A disabled item, such as Reset review while nothing differs from the original diff, is announced disabled, as a disabled Button is, so AT-SPI reports it neither enabled nor sensitive. A menu label, the text that titles or explains the items around it, is a label (`Role::Label`) and a separator a separator (`Role::Splitter`, AT-SPI's separator), so neither is counted or announced as one more, unavailable command. An item whose label says less than its button's accessible name takes that name with `PopupMenuItem::accessibility_label`: the narrow review Options menu's "More context (3 lines)" is announced "More context, 3 lines shown", as the full row's button is. A row a menu capped at its window's width cuts with an ellipsis, such as a long identity in the profile menu of a 461 px window, keeps its whole text as its accessible name. Up and Down move only between items that can act, from the first of them, so a menu that opens with a label, such as the project pane's row menu, takes its first Down to its first action. The [component patch](../vendor/gpui-component/GITTURTLE-PATCH.md) supplies the roles and the disabled flag; groups are not announced as exclusive, because the kit's API does not say whether they are.

The [macOS backend patch](../vendor/gpui-pre-macos/README.gitturtle.md#accessibility-responder-alignment) attaches AccessKit to GPUI's actual first-responder rendering view and initializes current host key-window state. The upstream adapter attached to its parent content view, which could expose the tree while focused controls still returned window-level fallback through AppKit. Native validation of the resulting binary remains necessary.

## Display preferences

On macOS, startup, foreground activation and public `NSWorkspace` display-option notifications read current preferences on the main thread. A single coalesced wakeup applies notifications through GPUI’s foreground executor without synchronously reentering an App borrow or polling. The view owns the observer and unregisters it on release. Reduce Motion updates the toolkit policy and pauses custom GIF and GLB playback. Manual frame controls and model seeking remain usable; Play is unavailable while Reduce Motion is enabled. Disabling Reduce Motion updates controls without silently resuming playback. GLB clip controls name their comparison side, and its seconds slider exposes keyboard seeking, range and current value. The [GLB workflow record](glb-workflow-validation.md) distinguishes native keyboard/metadata checks from spoken VoiceOver coverage. The app does not change system settings. Exact existing objc2 versions are reused through macOS-only dependencies.

Increase Contrast and Reduce Transparency are available to the read-only inspection bridge but do not select another app palette. Principal surfaces are opaque. Native validation must observe actual contrast, transparency, hover, selection and focus behavior under those settings; the presence of the OS getters does not establish compliance. Independent interface/code sizes, both densities, all twenty built-in themes and the theme picker with custom themes present remain part of the current visual matrix. Linux uses the portable semantic controls; the macOS settings bridge is conditional and no Linux desktop window pass is implied. On Linux, the desktop text scaling factor (GNOME Large Text) and the font antialiasing preference are read through the XDG settings portal, with a fontconfig fallback. Portal signals update the running app; focus return rereads the fallback and retries a missing portal; the [Linux runbook](linux.md#platform-limits) records the sources and limits.

## Verification

`cargo test --locked -p gitturtle native_accessibility` exercises bounded navigator traversal and rendered button accessibility metadata. `cargo test --locked -p gitturtle reduced_motion_pause` verifies that pausing keeps the current GIF frame until explicit resume. These are model and toolkit tests, not VoiceOver evidence.

The native owner must record the exercised binary/source, OS, initial settings and restoration. Traverse Projects, repository tabs, branch folders, History/files, Working Changes, comparison and Find, conflicts, Settings, command palette, Git confirmations and GitHub forms with VoiceOver and keyboard input. Verify spoken names/roles/states, current-row movement without whole-window repetition, text editing, modal containment and restored focus. Trigger a recoverable failure and completion notice; confirm each is announced once without polling noise. Inspect readable Markdown and PDF text alternatives, image absence, page/zoom controls, model toggles and errors. Exercise Reduce Motion before startup and through live ON/OFF changes; record actual Increase Contrast/Reduce Transparency behavior. Use disposable repositories for mutation tests and a separately authorized disposable hosted repository for GitHub writes.

Native acceptance covers minimum and wide window sizes, both densities, the twenty built-in themes and custom themes in the picker and the editor. Actual VoiceOver, settings, native mutation and package results belong in the active milestone record; unexecuted combinations remain explicit.

## Primary guidance

Apple’s [accessibility design guidance](https://developer.apple.com/design/human-interface-guidelines/accessibility/) and [VoiceOver guidance](https://developer.apple.com/design/human-interface-guidelines/voiceover/) support readable labels, navigable order and equivalent custom-control behavior. The implementation uses the public [display-options notification](https://developer.apple.com/documentation/appkit/nsworkspace/accessibilitydisplayoptionsdidchangenotification), [Reduce Motion property](https://developer.apple.com/documentation/appkit/nsworkspace/accessibilitydisplayshouldreducemotion), [Increase Contrast property](https://developer.apple.com/documentation/appkit/nsworkspace/accessibilitydisplayshouldincreasecontrast), and [Reduce Transparency property](https://developer.apple.com/documentation/appkit/nsworkspace/accessibilitydisplayshouldreducetransparency). [Apple’s VoiceOver evaluation criteria](https://developer.apple.com/help/app-store-connect/manage-app-accessibility/voiceover-evaluation-criteria) inform the native workflow checks; this document makes no certification or App Store declaration.

The pinned component Input also now projects its accessibility metadata onto the shared editing-state element that owns keyboard focus. Previously the role was on an outer frame and the editing focus target had no accessible node, so GPUI selected its window-root fallback. The frame remains a separate focus group; no duplicate FocusHandle is registered. The bounded [component patch](../vendor/gpui-component/GITTURTLE-PATCH.md) and [base patch](../vendor/gpui-base/GITTURTLE-PATCH.md) preserve version and Apache provenance. Synthetic rendered-node checks establish ordinary/password/multiline roles, names, identifiers and editable-action semantics on the actual editing focus owner; native macOS focus and VoiceOver behavior require the updated packaged executable.
