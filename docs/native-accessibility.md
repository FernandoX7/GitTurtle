# Native accessibility

GitTurtle’s current milestone includes VoiceOver, ordinary keyboard navigation and the available macOS display settings. Earlier dated milestone exclusions do not limit current work. Implementation and automated checks below are separate from the coordinator’s build-specific native evidence.

## Native semantics

The app uses the pinned GPUI Kit and AccessKit bridge. Custom controls need explicit stable IDs, roles and readable labels; drawing text is insufficient. A text field's placeholder is never its name: the kit names an unlabelled field after the placeholder it shows, which a narrow field shortens to whole words (the Changes and History filters read "Filter" at 18 pt in a 461 px window), so every field carries its whole name, such as "Filter working paths" and "Filter changed paths". In this toolkit version, anonymous text and `StyledText` do not create accessible nodes. Rendered Markdown therefore provides bounded readable prose, heading levels, code text, linearized table rows, image descriptions and separate Before/After documents. Exact Source remains available, and link buttons are separately reachable. PDF and model controls name their side, page or camera action; checked state is reserved for actual toggles.

History commits, changed files and working entries expose selected state, with exactly one current row reported as the active descendant of the focused list. Commit labels include subject, author, short identity and merge-parent count. Working multiselection retains all selected states while only the keyboard cursor owns active focus. The navigator is a tree with nesting and folder expansion state; Up/Down/Home/End skip section headings, Right expands or enters a folder, Left collapses or returns to its parent, Enter/Space activates, and Shift-F10 opens actions for the focused branch or worktree. Scope activation remains explicit. In History's changed-file list and the Working Changes list, Shift-F10, or on Linux the Menu key, opens the cursor row's menu below the row, the one a right-click opens, so a Working Changes row too narrow for its Stage or Unstage control keeps that action from the keyboard; the menu's first Down reaches its first action and Escape returns focus to the list (`native_accessibility::KeyboardMenu`, shared with the project list pane). The optional project list pane is a second tree with the same bindings and one tab stop: group rows report expanded state and project counts, the open project reports selected state, the cursor row is the active descendant, Shift-F10 opens the row's menu beside it and returns focus to the tree when it closes, and a refused edit or failed save is an assertive alert inside the pane. Warm repository tabs retain the cursor.

A container whose children can leave view is a node that clips them, with bounds that are the part of it the window draws (`native_accessibility::clips_children`): History's horizontal scroller, commit and changed-file lists, the Working inspector's file list, scrolling selection row and composer fields, the navigator and project list trees, the repository tab strip, Settings' page and the custom theme editor's columns, the Projects hub's body, the inspector's revision details, File History's header, revision list, failure notice and footer, Blame's lines and line history, and the GitHub panel with its pull request list, changed-file and patch lists, conversations, collected comments, saved drafts and previous attempts. In dialogs it covers the Reflog's content, entry list and changed-file list, every list cued by `tags::ScrollCue` (the branch chooser, remote manager, tags and tag push remotes), Activity's content and entries, the rebase plan, sequence and message, the comparison form, Quick Open's form and results, the command palette's and Keyboard Shortcuts' results, the profile manager and form, the worktree manager with its worktree and branch lists, the mainline parent choice, the stash and stash-file lists, the local workspace library, the rewritten-series body and list, the LFS download review, About's details, and the discard and force-removal reviews' scrolling explanations. A list the window renders only in part (a `uniform_list`) clips at the role-bearing list box or tree that holds its rows, so the rows stay that list's own children. Left out: scrolling text with no nodes inside (operation consequences, error and confirmation text), lists without a node of their own whose rows lie in a clipping page (Your themes, saved recovery drafts, a rewritten commit's files, recent projects), and documents read as a whole (rendered Markdown and PDF, model details, rich previews and the inspector's commit message), whose off-screen text a screen reader's continuous reading still needs while GPUI offers no scroll into view for the neighbour AccessKit keeps. GPUI gives each node its layout bounds and never marks clipping, so AT-SPI reported controls the window does not draw `visible` and `showing`, such as Reflog entries below the list and below the dialog, and a commit list running past the window's edge; a screen reader could find and activate them. AccessKit's filter leaves out a child wholly outside its clipping parent, except the first one past each edge, which it keeps for an assistive technology to move into, and a focused node wherever it lies. It compares a child with its nearest clipping parent only, so a viewport inside another, such as the Reflog's entry list in its scrolling content, reports the part the outer one shows. A partly visible control keeps its whole extents, as the platforms report one, except History's commit rows: each is as wide as the commit table, which runs sideways past the list's viewport, under the inspector and past the window's edge, so each row also reports the part of itself the list draws and clips what it holds, as the list does (AT-SPI reported rows to x 542.5 in a 461 px window at 13 pt, 630 at 18 pt and 681.5 in a 640 px window). `views::tests::history_rows_report_the_part_the_list_draws` checks every rendered row's node lies inside the list's. A container without a role of its own is a scroll view (an AT-SPI panel, a macOS scroll area); a list box keeps its role, and virtualized rows keep their position and set size. Focus and the Tab order do not change. AccessKit cuts a child only against its nearest parent that it does not pass over, so a group with a role between a clipping container, or a document read as a whole, and its controls clips too: the GitHub conversations section, the custom theme editor's readability warnings and the inspector's "Commit author and comparison parents", whose "Compare against parent 1" AT-SPI reached at 13 pt in a 461 × 490 window at y 346, below the commit details' visible bottom at 322.5 (with "Selected commit actions", since moved to the message's toolbar). `views::tests::commit_details_reach_only_the_controls_drawn` walks that group in History and Compare at 13 and 18 pt in 461 × 490 and at 640 × 490, and `theme_editor::tests::warnings_past_the_side_column_are_out_of_reach` the warnings past the side column, through AccessKit's filter. The Linux-only `reflog::tests::assistive_technology_reaches_only_the_entries_drawn` walks the Reflog's tree through the AT-SPI adapter, and the portable `settings::picker_tests::assistive_technology_reaches_only_the_settings_drawn` walks Settings in 640 × 490 and 461 × 490 windows through AccessKit's own filter: no theme card, switch or button lies wholly outside the part of the page the window draws, beyond the neighbour past each edge. Settings is a cached view only while no assistive technology is active, so the tree a client walks is drawn each frame. Orca and VoiceOver have not been checked.

An open modal dialog is the only content an assistive technology reaches. Every dialog (the Reflog, the rebase form, the GitHub panel, the command palette, Quick Open, Keyboard Shortcuts, the discard and worktree-removal reviews, the Settings dialogs and the rest) opens through the kit's one dialog layer, which the window draws beside the page rather than in it, and the page, everything from the tab strip to the bottom strip, is a node that is hidden while any dialog is open (`native_accessibility::beneath_modal`). The dialog's own node is modal, which AccessKit's adapters only report (AT-SPI's `modal` state, macOS's `AXModal`): the rest of the window stayed in the tree, so with the Reflog open AT-SPI still reached History's commit list and its rows, and a screen reader could browse and activate controls the dialog covers. Every adapter leaves out a hidden node with all it holds. While nothing covers the page, its node is a generic container, which AccessKit passes over, so the tree is the one it was. The copy announcement stays at the window root beside the page, so a copy made in a dialog is still announced. Focus and the Tab order do not change, and Escape still returns focus to the opener. `reflog::tests::an_open_reflog_leaves_the_page_it_covers_out_of_reach` walks the window's tree with the Reflog open and closed through AccessKit's filter, and on Linux through the AT-SPI adapter; Orca and VoiceOver have not been checked.

Projects exposes named Open/Clone/Create tabs, persistent field names even after values replace placeholders, readable section and empty-state descriptions, and the complete proposed destination. Its scrolling body reveals focused creation fields, Browse, action tabs and submit controls from measured bounds, including enlarged controls at the minimum window size. The reveal runs once after focus or viewport/text geometry changes; manual scrolling with unchanged focus does not snap back. Recent-project counts use a polite status node; validation and unavailable-folder failures use an assertive alert. Closing the last repository tab focuses the visible Projects root so application shortcuts continue to work. Native speech and keyboard checks remain necessary for the exercised build.

The command palette keeps input focus in its query while exposing a polite status node containing the selected command, position and disabled reason. Moving among results does not steal text input. Operation failures and input validation use assertive alerts; completion notices, conflict position/storage state and explicit document-navigation results use polite status nodes. So does Toggle Sidebar refused in a History window too narrow for navigation, which changes nothing on screen: the rail announces "Branches and worktrees unavailable: widen the window" with a fresh node for each press, so a repeated press is heard again. That node sets the text as both its name and its value, because AccessKit's adapters announce different properties when a live node is added: AT-SPI (Orca) announces the name, macOS the value. VoiceOver has not yet been checked on it. Every copy action is announced the same way: one node at the window root says "Copied ‹what›", such as "Copied commit hash", as both name and value, a fresh node for each copy, removed 1.5 s later as the copy button reverts; the button keeps its accessible name while it reads Copied. A focused list's Copy is announced the same way, without a button. A Git action a control asked for (a working file's Stage or Unstage, Stage all, Unstage all, Fetch, Pull, Push, Create, Switch, the branch picker's switch) is announced from that same node with its outcome, such as "Fetched origin" or "Staged notes.txt", once Git reports success, while the control reads its confirmation and keeps its accessible name; the window-wide completion notice, itself a polite status node, stays down for it, so the outcome is heard once. A copy made in a dialog is announced from that root node, outside the dialog's subtree. Neither Orca nor VoiceOver speech of these announcements has been checked yet. Continuous rendering progress has live announcements disabled to avoid repeated speech during camera motion. The portable `a11y_synthetic_children` hook sets existing parent-node live properties; it does not create an unbounded status history.

Git-write confirmation titles and consequences, authentication prompt text and SSH host-verification guidance are readable nodes. Secret inputs retain their password content type; their values are never copied into accessibility labels. Conflict side choices name the actual side and distinguish block-draft edits from reviewed whole-file replacement/staging.

## Toolkit patch

The pinned `gpui-base` Button previously prevented disabled activation but omitted AccessKit’s disabled flag. The focused [vendored patch](../vendor/gpui-base/GITTURTLE-PATCH.md) adds that flag while delegating the original rendering and interaction behavior, retaining Apache-2.0 notices and dependency versions. The actual rendered-node regression checks role, label, disabled metadata, absence of disabled click actions and selected/unselected Tab metadata. Tab roles map existing selected presentation to native selected state; ordinary buttons do not acquire selected or pressed semantics. The focus-trap wrapper also forwards its accessible role, metadata and synthetic children, and marks Dialog/AlertDialog roles modal. Its previous omission could leave the focused dialog host absent from the tree and produce window-level fallback focus. A wrapped-node regression covers named dialogs and generic groups. Native traversal must still verify containment, restored focus and discovery of unavailable controls. On Linux the pinned AccessKit AT-SPI adapter, `accesskit_atspi_common` 0.19.1, reported every disabled Button `enabled` and `sensitive`, and a disabled Switch, CheckBox or text input `read-only` ([September 30](validation.md#september-30-tab-leaves-a-focused-button-that-turns-disabled)). A [vendored backport](../vendor/accesskit_atspi_common/GITTURTLE-PATCH.md) of the upstream fix reports none of these on a disabled control, and enabled controls keep `enabled` and `sensitive`. The Linux-only `native_accessibility::atspi_state_tests` checks the adapter's state sets, and [October 1](validation.md#october-1-disabled-buttons-report-disabled-to-at-spi) records the native AT-SPI read. The kit's Checkbox and Switch do not set AccessKit's disabled flag yet, so a disabled check box or switch still reads as enabled on Linux. VoiceOver on macOS and Orca speech are not covered.

Persistent presentation selection and semantic toggle state are separate toolkit properties. Apply `.toggled` only to real switches or modes, and explicit tab/selected roles for repository tabs. An action such as Fit or Reset must not be announced as an unchecked toggle merely because it is unselected visually.

Menus follow the same rule. An item built with `PopupMenuItem::checked`, or through the kit's `menu_with_check` builders, is a check menu item (`Role::MenuItemCheckBox`) whose toggled state follows its tick; every other item stays a plain menu item, so a menu that ticks a choice marks each of its choices checkable (the branch chooser's other branches take `.checked(false)`), and a command beside them, such as the review Options menu's More context and Reset review, stays plain. A disabled item, such as Reset review while nothing differs from the original diff, is announced disabled, as a disabled Button is, so AT-SPI reports it neither enabled nor sensitive. A menu label, the text that titles or explains the items around it, is a label (`Role::Label`) and a separator a separator (`Role::Splitter`, AT-SPI's separator), so neither is counted or announced as one more, unavailable command. An item whose label says less than its button's accessible name takes that name with `PopupMenuItem::accessibility_label`: the narrow review Options menu's "More context (3 lines)" is announced "More context, 3 lines shown", as the full row's button is. A row a menu capped at its window's width cuts with an ellipsis, such as a long identity in the profile menu of a 461 px window, keeps its whole text as its accessible name. Up and Down move only between items that can act, from the first of them, so a menu that opens with a label, such as the project pane's row menu, takes its first Down to its first action. The [component patch](../vendor/gpui-component/GITTURTLE-PATCH.md) supplies the roles and the disabled flag; groups are not announced as exclusive, because the kit's API does not say whether they are.

The [macOS backend patch](../vendor/gpui-pre-macos/README.gitturtle.md#accessibility-responder-alignment) attaches AccessKit to GPUI's actual first-responder rendering view and initializes current host key-window state. The upstream adapter attached to its parent content view, which could expose the tree while focused controls still returned window-level fallback through AppKit. Native validation of the resulting binary remains necessary.

## Display preferences

On macOS, startup, foreground activation and public `NSWorkspace` display-option notifications read current preferences on the main thread. A single coalesced wakeup applies notifications through GPUI’s foreground executor without synchronously reentering an App borrow or polling. The view owns the observer and unregisters it on release. Reduce Motion updates the toolkit policy and pauses custom GIF and GLB playback. Manual frame controls and model seeking remain usable; Play is unavailable while Reduce Motion is enabled. Disabling Reduce Motion updates controls without silently resuming playback. GLB clip controls name their comparison side, and its seconds slider exposes keyboard seeking, range and current value. The [GLB workflow record](glb-workflow-validation.md) distinguishes native keyboard/metadata checks from spoken VoiceOver coverage. The app does not change system settings. Exact existing objc2 versions are reused through macOS-only dependencies.

Increase Contrast and Reduce Transparency are available to the read-only inspection bridge but do not select another app palette. Principal surfaces are opaque. Native validation must observe actual contrast, transparency, hover, selection and focus behavior under those settings; the presence of the OS getters does not establish compliance. Independent interface/code sizes, both densities, all twenty built-in themes and the theme picker with custom themes present remain part of the current visual matrix. Linux uses the portable semantic controls; the macOS settings bridge is conditional and no Linux desktop window pass is implied. On Linux, the desktop text scaling factor (GNOME Large Text) and the font antialiasing preference are read through the XDG settings portal, with a fontconfig fallback. Portal signals update the running app; focus return rereads the fallback and retries a missing portal; the [Linux runbook](linux.md#platform-limits) records the sources and limits.

## Verification

`cargo test --locked -p gitturtle native_accessibility` exercises bounded navigator traversal and rendered button accessibility metadata. `cargo test --locked -p gitturtle reduced_motion_pause` verifies that pausing keeps the current GIF frame until explicit resume. These are model and toolkit tests, not VoiceOver evidence.

The native owner must record the exercised binary/source, OS, initial settings and restoration. Traverse Projects, repository tabs, branch folders, History/files, Working Changes, comparison and Find, conflicts, Settings, command palette, Git confirmations and GitHub forms with VoiceOver and keyboard input. Verify spoken names/roles/states, current-row movement without whole-window repetition, text editing, modal containment and restored focus. Trigger a recoverable failure and completion notice; confirm each is announced once without polling noise. Inspect readable Markdown and PDF text alternatives, image absence, page/zoom controls, model toggles and errors. Exercise Reduce Motion before startup and through live ON/OFF changes; record actual Increase Contrast/Reduce Transparency behavior. Use disposable repositories for mutation tests and a separately authorized disposable hosted repository for GitHub writes.

Native acceptance covers minimum and wide window sizes, both densities, the twenty built-in themes and custom themes in the picker and the editor. Actual VoiceOver, settings, native mutation and package results belong in the active milestone record; unexecuted combinations remain explicit.

## Primary guidance

Apple’s [accessibility design guidance](https://developer.apple.com/design/human-interface-guidelines/accessibility/) and [VoiceOver guidance](https://developer.apple.com/design/human-interface-guidelines/voiceover/) support readable labels, navigable order and equivalent custom-control behavior. The implementation uses the public [display-options notification](https://developer.apple.com/documentation/appkit/nsworkspace/accessibilitydisplayoptionsdidchangenotification), [Reduce Motion property](https://developer.apple.com/documentation/appkit/nsworkspace/accessibilitydisplayshouldreducemotion), [Increase Contrast property](https://developer.apple.com/documentation/appkit/nsworkspace/accessibilitydisplayshouldincreasecontrast), and [Reduce Transparency property](https://developer.apple.com/documentation/appkit/nsworkspace/accessibilitydisplayshouldreducetransparency). [Apple’s VoiceOver evaluation criteria](https://developer.apple.com/help/app-store-connect/manage-app-accessibility/voiceover-evaluation-criteria) inform the native workflow checks; this document makes no certification or App Store declaration.

The pinned component Input also now projects its accessibility metadata onto the shared editing-state element that owns keyboard focus. Previously the role was on an outer frame and the editing focus target had no accessible node, so GPUI selected its window-root fallback. The frame remains a separate focus group; no duplicate FocusHandle is registered. The bounded [component patch](../vendor/gpui-component/GITTURTLE-PATCH.md) and [base patch](../vendor/gpui-base/GITTURTLE-PATCH.md) preserve version and Apache provenance. Synthetic rendered-node checks establish ordinary/password/multiline roles, names, identifiers and editable-action semantics on the actual editing focus owner; native macOS focus and VoiceOver behavior require the updated packaged executable.
