## Extending a decoder

Keep format-specific parsing, validation and optional resource handling in the owning decoder modules. Public decode results carry owned data and explicit unsupported, absent or truncated states; they must not acquire repository handles, app state or native UI types. Git core captures repository content and local assets, while the app owns scheduling, cancellation generations and cache retention. Share pixel, geometry or budget helpers only when their format semantics agree.

## Decoder contracts

- `decode_image` consumes supplied bytes. The filename is a format hint, never a path to open; raster magic takes precedence. `detect_lfs_pointer` returns metadata only. Verified local LFS resolution belongs to [Git core](../git-core/AGENTS.md), and missing sides must remain distinct from empty image bytes in the caller.
- Keep source-byte, source-dimension, decoded-allocation, and output-dimension limits independent. Reject unreasonable headers before decoding pixels and validate SVG complexity before rendering. Codec allocation limits are best effort, not a process-memory sandbox or wall-clock deadline. Run decoding on bounded background workers.
- `ImagePreview.rgba` is straight RGBA8. Preserve transparency, premultiply while resizing to prevent invisible colors bleeding into edges, then return straight alpha. Keep aspect ratio, never enlarge previews, and apply raster orientation before reporting original dimensions. `decode_image` retains first-frame GIF behavior; `animation::decode_gif` separately bounds composed frames, elapsed duration, aggregate source/output pixels, and cooperative decode time. GPUI's BGRA conversion belongs to [the app worker](../app/src/worker.rs).
- SVG previews are static and self-contained. Preserve explicit refusals for DTDs, linked or embedded image resources, nonfragment `href` values, and filters; disabling `resources_dir` alone does not prevent absolute-path reads. Bound `use` and marker expansion before usvg and font loading, independently from XML size/depth. Keep renderer-compatible namespace/fragment resolution and refuse marker CSS that the structural preflight cannot account for. Keep both image resolvers disabled and load system fonts once, only when text appears. Adding unsupported features requires bounded behavior and honest preview results.
- Native ImageIO, CoreGraphics and PDFKit references remain on one worker stack and consume supplied CFData only. Return owned pixels/text; never send native document references to the UI. PDF pages are capped independently from source bytes and pixel bounds, with cancellation between phases. [Selected-page text](src/native/pdf_text.rs) uses a scoped autorelease pool and caps returned UTF-8 independently at 256 KiB; absence and truncation stay explicit. Text-layer order may differ from visual layout; no OCR is requested. Generic container metadata never decompresses archives, installs fonts or executes document actions. Dedicated 3MF geometry decoding may decompress bounded selected XML members in memory, with no filesystem extraction. `metadata::container` names the leading signature without the file name for the app's Linux handoff to a default application; there is deliberately no office package identification, since OOXML and OpenDocument bodies reach outside the package where no bounded manifest check sees it ([why](../../docs/file-previews.md#background-work-and-resource-lifetime)). Decoded UTF-16 and PDF text are explicitly transformed source and never a Git patch.
- Linux on x86-64 and AArch64 renders PDF pages with hayro only inside GitTurtle's confined helper process: `pdf_helper::serve` is the one public way into [src/pdf_hayro.rs](src/pdf_hayro.rs), and `decode_pdf_page`/`decode_pdf_page_text` keep refusing on Linux, so nothing runs hayro in the app process. Other targets build neither module nor hayro. hayro has no memory budget or cancellation and some hostile inputs abort or never finish; the helper's limits and the client's deadline stop those, while each phase turns a Rust panic into an error kind. Keep the macOS page contract (crop box, rotation, white background, the 1,000-pixel edge from `render_dimensions()` before rasterizing plus `check_dimensions`, no annotations or actions) and the 256 KiB text cap at a character boundary with explicit truncation and absence. The helper checks the input size, page bound and `%PDF-` signature before allocating the body; `read_reply` checks every size against the page and text bounds before allocating and refuses trailing bytes. Error replies carry fixed kinds only, which the client words itself. Change `PROTOCOL_VERSION` with any frame.
- Linux on the same targets decodes AVIF (`mp4parse` 0.17.0 and the system libdav1d through dav1d-rs) and JPEG 2000 (`hayro-jpeg2000` 0.4.1) only in that helper: `serve` reads the magic and dispatches to [src/image_helper.rs](src/image_helper.rs); `confined_image_format` is the single routing decision (AVIF, JP2, J2K, never HEIF), and `decode_image` keeps refusing all three, and HEIF with its own sentence. The decoding modules stay private with `#![forbid(unsafe_code)]`; `libdav1d_version` in `lib.rs` is the one `unsafe` call, and the helper refuses libdav1d before 1.4.1 before `mp4parse` runs. The request is refused before its body is allocated, in order: header, version, format, edge (1 to 1,600), length, then a 4,096-byte prefix sniff. `read_image_reply` accepts only the requested format's echo, kinds and flags, an original passing the source bounds, an output of exactly `scaled_dimensions` at the client's edge, and no trailing bytes. dav1d: fresh `Settings` with one thread, frame delay 1, `frame_size_limit` of the `ispe` area, operating point 0, all layers off, grain on, invisible frames off; one decoder per item and a bounded send/get loop. The only dav1d-rs calls are those setters, `Decoder::with_settings`, `send_data`, `send_pending_data`, `get_picture`, and the `Picture` accessors `width`, `height`, `pixel_layout`, `bits_per_component`, `bit_depth`, `stride`, `plane`, `matrix_coefficients`, `color_range`, `color_primaries` and `transfer_characteristic`; never a custom allocator, the sequence-header parser or other picture metadata (`dav1d-sys` layouts are hand-written, #126). A picture must equal `ispe` before any plane is read, and a monochrome picture or alpha item reads luma alone; the primary is converted, and its picture freed, before the alpha item is decoded, and each converter consumes its picture, so at most one dav1d picture is alive beside the RGBA image, the primary's while it converts and then the alpha's, never both items' pictures (requirement 18's peak; with film grain, an item's decoder also holds its ungrained reference until the decode returns). An ICC `colr` profile of at most 4 MiB (checked before moxcms parses it) that describes RGB converts the RGBA to sRGB in place, in place of the `nclx` or sequence-header primaries and transfer; one that is larger, malformed, not RGB or panics moxcms while it parses the profile or builds the transform draws without it and flags "colour profile not applied". A panic while the transform runs fails the image as `DecoderFailed`, contained by `serve`'s `catch_unwind`; the helper serves one request per process, so no half-converted pixels leave it. `avif.rs` is the only module that calls moxcms directly (the source test holds it). JPEG 2000 decodes through `Image::new` and its `ImageDecoder` reads after the preflight (JP2 compatibility, one `jp2h` and then one `jp2c` with neither kind after it, bytes that frame no box refused before the `jp2c` and ending the walk after it as they end hayro's, `ihdr` and SIZ agreement, origins, at most 65,535 tiles by B-5, 1 to 4 components of at most 16 bits, the `pclr` checks (unsigned columns: hayro drops a palette with a signed one and decodes the components as they are), a `cmap` of 1 to 4 entries naming components and columns that exist, at most one `cdef`, and the 256 MiB budget of one f32 plane per component and per `cmap` entry, or twice the output planes when a `cdef` makes hayro copy them and that is more; when the first `colr` makes hayro convert through a profile, the planes and 8-bit copy of one decode beside a second decode, as `profile_planes` derives; when hayro reads the colour space as CMYK and converts it without a profile (`reads_as_cmyk`: with a palette, the CMYK or YCCK space, or no `colr` or an unknown method with four columns; without one, four components under those spaces, under greyscale, or with no `colr` or an unknown method, since hayro repairs three to RGB and one to grey), at least the output planes, their 8-bit copy and moxcms's sRGB result, `output + ceil(output / 4) + 1` planes, or `2 × output + 1` when a palette and a `cdef` whose last channel by index is opacity (`opacity_last`, hayro's `has_alpha`) leave alpha beside CMYK, as `cmyk_planes` derives; hayro's copies of an ICC profile's bytes are not budgeted, since they do not grow with the image and each is bounded by the 32 MiB input), at reduced resolution only with 1 × 1 sampling and no palette; never through its hook-registered decoder. A source test in `avif.rs` refuses the forbidden entries and, against its list of dav1d-rs 0.11.1's public functions, any dav1d-rs call or item outside those above. It reads the words and paths of every preview source outside comments and its `#[cfg(test)]` `tests` module, which it finds without comments and literals and reads past, so a name outside the list counts however its call is qualified (`<Picture>::`, `Decoder::<_>::`) or split by a comment, and so does every rename (`type`, `use … as`, `extern crate`, `::dav1d`). No preview source includes a file (the word `include` anywhere outside literals, so `std::include!` and `use … include as` count too), takes a module from a `path` in any attribute, however nested (`#[path]`, `#[cfg_attr(…, path = …)]`), or defines a `macro_rules` macro (the word anywhere outside literals), which could build such an attribute from its arguments (`#[$a]`, `#[$a = $v]`, `#[$($t)*]`) or assemble a dav1d-rs path; and the crate has no build script, which could set `--cfg test` (Cargo sets no `OUT_DIR` for it, and `cargo metadata` lists no `custom-build` target), and its library root, as `cargo metadata` reads the manifest, is `src/lib.rs`, so nothing roots it outside `src/`. So every file compiled into the crate is a `.rs` source the scan reads. `dav1d` appears only in `src/avif.rs` and `dav1d_sys` only in `lib.rs`'s version call. Every `src/avif*` source is read by `avif.rs`'s rules: it makes nothing but `decode` public, declares no module and reads no file's text or bytes (`include_str`, `include_bytes`). The scan expands no macro: those the crate calls come from the standard library and its reviewed dependencies. An ABI probe compares `dav1d-sys` with the installed headers and prints the host CPU's feature flags and the libdav1d version for the hosted log. Fixtures come from `scripts/create-image-codec-fixtures.py`.
- Mermaid retains exact literal source separately from its static diagram. Bound source/graph complexity before layout and generated SVG before rasterization. Refuse source configuration/actions/resources; do not call the renderer's filesystem/CLI helpers or restore its disabled disk font cache. Keep cancellation between phases and individual diagrams, with honest errors/caps and no claim of complete Mermaid compatibility.
- Mesh/CAD decoders never load repository-relative materials, textures, geometry references, scripts or caches. Bound expanded geometry and raster work independently of compressed input bytes and preserve finite coordinates, supported transforms and explicit units. STEP retains its finite supported geometry/placement contract; refuse unsupported geometry rather than inventing a bounding box or point cloud. Label tessellated analytic geometry, default poses and unknown physical scale honestly.
- GLB validation keeps structural geometry failures separate from optional appearance or animation failures. Invalid skins and morph geometry must fail rather than show an undeformed substitute; an unavailable optional texture or clip can retain valid default geometry with a specific disclosure. Cancellation still propagates through those fallback paths. Embedded texture pixels retain glTF's encoded orientation and color interpretation; do not apply the standalone raster orientation policy to them. Preserve the disclosed distinction between unlit materials and simplified base-color inspection.
- `decode_geometry` returns immutable retained `ModelScene` data; interactive consumers evaluate the requested animation time with `ModelScene::evaluate_animation` and render the requested camera through `render_model` on a cancellable worker. Account for geometry, appearance, texture mipmaps and deformation data with `ModelScene::retained_bytes`, and bound output pixels separately. Keep compressed input, expanded accessors, retained resources and per-frame raster work independently bounded. Meshopt's bounded native whole-stream calls cannot be interrupted; checks around them are cooperative cancellation, not a hard deadline.
- Initial linked cameras fit both revisions' union bounds so normalization cannot hide size or position changes; preserve explicit independent-camera inspection. Evaluating a pose must not reset the camera or precompute a cache of every animation frame. `decode_model` retains fixed views for secondary static consumers. Views remain inspection aids rather than geometry edits or manufacturing validation.

## App icon consumer

[examples/render_icon.rs](examples/render_icon.rs) is a standalone decoder example for square images of at least 1024 pixels and preserves alpha. The production icon uses layered `assets/AppIcon.icon`; follow the [asset conventions](../../assets/icons/README.md) for its render and package pipeline. The decoder example does not produce the native appearance catalog.

## Verification

Run `cargo test --locked -p gitturtle-preview` or a relevant filter for decoder changes. Focus fixtures on output pixels/dimensions, supported format behavior, and refusal boundaries; use the root final checks for Rust integration. Guidance-only edits need link, symbol, and diff checks. Native QA applies when image presentation or the packaged icon changes, not to every decoder edit.
