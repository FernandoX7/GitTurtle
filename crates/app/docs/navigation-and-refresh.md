# Navigation and refresh contracts

Read this when changing or reviewing page/mode transitions, focus, selection, worker scheduling, search, retained inspections, or local refresh. Source ownership is mapped in [app guidance](../AGENTS.md); the broader flow is in [architecture](../../../docs/architecture.md).

## Selection and asynchronous replies

Commit selection in History requests `Job::Changes`; a highlighted file is not an activation. Explicit activation enters Compare. Choosing the file whose comparison is still being read keeps that read (`GitTurtle::reads_preview_of`): the same file of the same repository against the same revision pair reads nothing new, while another file, or the same one against another pair, is read in its place. A file chosen again while the reader still decodes its image in this process, after another file was chosen in between, is answered by that preparation: the window asks for it again, and the worker gives the request to the preparation under way rather than starting a second one (`Worker::submit`, `worker::Preparation`), so its bytes are decoded once and the file chosen in between is never read. An image decoded in this process checks nothing until it ends, so choosing another file only marks that phase superseded (`Cancellation::unobserved`), and a preparation still superseded as it ends stops then and is prepared anew when its file is chosen again. Every other phase of a preview's preparation stops as soon as another file is chosen, as Back cancels the read and as a tab closes, its token cancelled as any read's is: a Markdown document's image capture with its Git reads, the confined helper's decode, which checks every 25 ms, a GIF's frames (`worker::image_tests::a_preview_chosen_again_while_it_is_prepared_is_prepared_once`, `superseding_back_and_closing_stop_a_previews_token_watching_work`). The decode once ran on after another file was chosen and was thrown away, so a file chosen away from and back to during it had its bytes decoded twice. Back keeps the comparison already shown, except one whose text review is still being prepared, which it drops with the review's options, so choosing the file again reads it again. A text review whose preparation ends otherwise without its result, its read failing (past the review's limits) or dropped unanswered, or abandoned as Blame opens over the comparison, Quick Open inspects a tracked file or another repository tab is shown, each keeping the comparison for its return, drops its options and gives the shown diff's partial actions back (`GitTurtle::release_text_review`), since that diff is the one they act on. A partial action that reads enabled acts on its first press, and one that cannot act reads disabled: a press acts on the diff it was made on only while the window shows that diff for the selected Working row (`GitTurtle::shows_partial`, through the one subscription `bind_text_partial` makes as the view is built), whatever reads move the window on meanwhile, and a refused press leaves the actions suspended. Each action is placed from where the diff's gutter last painted, which a refresh keeps (`DiffView::refresh_numbered`), and a gutter paint that finds that origin moved, its first or one after the view was laid out anew, asks for the frame that draws them in place. Left suspended, they stayed refused until another file was chosen; bound to the window's read as the view was built, they had to be bound again at every read that left the diff shown; and placed from the text's origin after a refresh while hidden, each was drawn 8 px above its row (at the default size) in the one frame Quick Open's return draws, so the pointer's arrival moved Stage from under it and its first press started nothing (QA-101 F1, `text_review::tests::quick_open_behind_a_held_read_keeps_the_first_press`). Back cancels any preview read still in flight, whatever its label (`GitTurtle::preview_in_flight`, recorded from the job by `request`): a comparison's own (`PREVIEW_LABEL`), one restored with its tab (`RESTORED_PREVIEW_LABEL`), a tracked or working file's, or a text review's preparation; the comparison it was for is not kept, nor a restored one's document bookmark; `receive(Output::Preview)` still drops a reply that lands once the mode is neither Compare nor Working. A reply that lands while another page is shown over Compare is kept, without building its editor; the return (`resume_repository_page`) builds it and, for a restored comparison, restores its documents then, while one still being read keeps its bookmark for its reply. Preserve generation checks and both the `AppPage::Repository` and workspace-mode guards when changing asynchronous code.

Back from Compare restores the retained scope, query, loaded history, selection, scroll position, and inspector without another Git request. Working Changes keeps history files separately in `retained_history_files`; do not reuse mutable working files as the history inspector. History-changing writes use `refresh_after_write` to queue a quiet refresh, preserving the valid selected scope, pinned query, and immutable comparison. Re-resolve mutable branch/worktree identities; session reuse must not freeze tips. Parent changes keep the displayed comparison and selected file consistent. Rebuild selections from stable commit/file identity rather than virtualized row indices.

Working-status replies check both `work_generation` and canonical repository identity. Refresh and writes use `invalidate_read` to advance the preview generation and cancel obsolete work when mutable content is invalidated, even when the next selection is empty. Retain the user's current path/area at reply time, including movement between staged and unstaged groups; do not restore the selection captured at dispatch. Mutable previews bypass the immutable cache.

## Worker and observer ownership

Bounds apply at each owner's scope, not automatically to the whole process. Trace the owning state and its cancellation/release path before adding background work:

| Work | Current owner and lifetime |
| --- | --- |
| History, selected previews, search and quiet reads | Each window's `GitTurtle::worker`; tabs share that reader and invalidate obsolete work when switching. A History snapshot reads its tags on one scoped thread beside its history page, under the same cancellation, and joins it before returning. |
| Accepted Git writes and preference saves | Separate `SerialExecutor` instances created by each `GitTurtle`; accepted writes drain after a reply is dropped. This is not a process-wide Git transaction lock. |
| Changed/working path filtering | The window's lazy `path_filter::State` executor, with snapshot identity and cancellation tickets; working filtering reuses this lane. |
| Later PDF pages and model frames | Separate process-wide `OnceLock` renderers in `pdf_view::renderer` and `model_view::renderer`; content owners retain their own caches, generations and cancellation. A shared lane does not make retained view memory global or free. |
| Stash inspection | The dialog's `StashBrowser` owns a metadata executor and preview `Worker`; replacement/closure must also pause retained documents. |
| Reflog inspection | The dialog's `ReflogBrowser` owns a `SerialExecutor` and submits one read to it at a time: a read asked for meanwhile cancels the one running and waits in place of any earlier request until that one answers, so key repeat on the entry list cannot fill the executor's bounded queue. Cancel and closing the dialog cancel the running read and drop the waiting one. An arrow key's repeats on the entry list (`KeyDownEvent::is_held`) select entries but submit nothing until that key comes up (the repeat records its key, so another key's key-up ends nothing) or `REPEAT_PAUSE` (150 ms) passes without a repeat, so a held key starts one read when it stops rather than one Git process per repeat; GPUI's X11 backend marks no key event as a repeat, so there each repeat reads as a press does. |
| Linux desktop preferences | One app-global `desktop_text::Observer`; see [desktop observers](#desktop-observers). |

New read jobs need a captured identity, a bounded queue/input/result and a terminal path for supersession, error and owner release. Keep accepted writes on their existing path. Do not add a second persistence or Git policy implementation to a native view merely because it uses a separate executor.

## Pages and focus

Projects and Settings are pages separate from the retained repository modes. Construct elements only for the active `AppPage`; calling a hidden page renderer still builds its lists, controls and previews. Keep the root `app_focus`, history `focus`, and `file_focus` handles distinct. Settings focuses its first control (Follow system appearance, or the selected theme's card while the desktop's Omarchy theme makes that switch unavailable) and Projects its selected action tab, both inside the root, so application shortcuts remain reachable and each page opens with its focus drawn; Settings marks that focus on the window's `FocusRing` and reveals it in its page however it was opened, every time it opens (`FocusReveal::reveal_next_focus` reveals even the control the page last drew focused, since the page reopens at its top). Keep `GitTurtleList` navigation out of editable form fields; hidden editors must not steal focus. Retain the selected file's visibility as lists change. Temporary search expansion must not overwrite saved branch-folder expansion choices.

On Linux, use compositor-provided window decorations when available. Otherwise the repository-tab strip supplies accessible window controls on every page, following the desktop's button placement/order and the compositor's supported minimize/maximize actions. Blank header space supports dragging, double-click maximize and the native window menu. Close uses the existing Close Window action and normal shutdown observers and is disabled while a Git operation is running. macOS retains its native title bar, traffic lights and application menu; the primary-modifier Quit shortcut remains available on both platforms.

Folder-picker cancellation retains the current repository and form input. Request failures surface on the current page, with Linux FileChooser service guidance and a command-line path fallback. Linux startup without a graphical session exits with a diagnostic; Git askpass dispatch still happens before this check.

Switching between History, Working Changes and Settings only reads, so a running write leaves it available from every route: the shortcuts, the header's toggles, the palette, both platforms' menus and the empty-state and paused-operation actions that open Changes (`page_navigation::tests::page_switches_stay_available_while_a_write_runs`). ## Desktop observers

`desktop_text::start` installs safe defaults before its bounded initial wait. Linux portal setup, signal reads and `fc-match` fallback run in one app-owned background task; foreground application takes only the latest snapshot. Its one portal session subscribes to `SettingChanged` without a namespace filter, so every key arrives on one ordered stream that `change` selects from, and it reads the text keys and the five motion and contrast keys (`desktop_text::Observed`) in one `join!` under the same 250 ms deadline; a signal during those reads wins over its key's read. Only a text key's change runs `fc-match` again; a motion or contrast change alone never does. Once a session has answered, a refresh whose connection fails or outlives that deadline keeps its answer, text keys and fontconfig fallback included, and sends no snapshot, so the desktop's preferences hold until a refresh connects again; a desktop that never answered resolves without portal values, the motion and contrast preferences off, at every attempt. Each snapshot carries the resolved `DisplayPreferences` (`Observed::display`); `apply` hands them to `native_accessibility`, which keeps them in one app global (absent until a snapshot is applied, the launch defaults included, so a window's activation leaves the toolkit's motion policy alone until then, as in tests, which never start the observer) and stays the one place that sets that policy (`sync_preferences`). Each `GitTurtle` window observes the global and pauses playback when it changes (`apply_motion_preferences`), as macOS's display-change notification does; an unchanged answer touches nothing. Coalesce wakeups, cap work per signal batch and yield so a continuously ready source cannot starve cancellation. Focus regain requests one refresh and retries an unavailable portal, and so does a change to the user's fontconfig configuration: the same task watches `$XDG_CONFIG_HOME/fontconfig` (or `~/.config/fontconfig`), and that directory's parent while it does not exist, and requests a refresh once writes there settle for 250 ms, ignoring reads so `fc-match` cannot trigger itself (`desktop_text::user_fontconfig`). Do not introduce idle polling. Child queries have time and output limits, are read on the executor's timer rather than blocking a worker thread, and are killed and reaped when they fail, outlive their bound, are dropped or the app exits. A query ends once its child has exited and the pipe is drained, not when the pipe closes: a process another thread spawns while the child starts holds a copy of the pipe's write end until that process execs (`desktop_text::portal::tests::a_query_ends_with_its_child_while_another_process_holds_its_pipe`). The observer cancels and joins its worker during app shutdown. While Settings asks for the desktop's monospace font, the same task runs one bounded `fc-match monospace` per connection (at launch, on focus regain and when the setting turns on, never per portal signal), after that connection's first snapshot, so launch never waits on it. The task awaits each query, so at most one `fc-match` runs at a time and a focus regain during a lookup waits for it. Without a fontconfig cache that lookup scans every font directory first (about 0.8 s on the [cold-launch record](../../../docs/benchmarks/2026-09-29-code-font-cold-launch.md)'s host), so its bound is `portal::FAMILY_WAIT`, 4 s: Settings shows it pending until it answers, and unavailable only when that bound runs out. Turning the setting off, or off and on, stops a running lookup (`desktop_text::portal::tests`, `settings::picker_tests::the_code_font_row_stays_pending_through_a_slow_lookup`). It accepts the first listed family that the toolkit's `all_font_names` includes and that draws basic Latin at one advance, and never looks up an unlisted name, because the toolkit caches a failed lookup for the process. Each reply carries the generation of the setting it answers, and `apply_code_font` drops one for a setting since turned off or off and on (`desktop_text::tests::the_code_font_follows_the_setting_and_survives_theme_changes`).

`appearance::omarchy` owns the desktop's Omarchy theme on Linux in one app-level global that the picker card, the Follow system switch and `apply_appearance` read. It reads `~/.local/state/omarchy/current/` on the background executor at launch (launch waits up to 200 ms for that read only when the Omarchy theme is selected), on focus regain, when a watch starts and when the card is chosen. It watches that directory without recursion while the Omarchy theme is selected, and while Settings is open: Settings starts the watch while it offers the card and keeps a running watch when a read withdraws the card (`theme/` gone for longer than the quiet period mid-switch, or a state migration), so the theme coming back offers the card again without a focus return. Closing Settings drops the watch unless the theme is selected. While the card is not selected, a watched reread updates its caption and miniature and applies nothing. Rereads run one at a time: a watched write that can change the theme (`theme/` or `theme.name`, never `background` or `next-theme`) waits for a 250 ms quiet period on the GPUI timer that each further write restarts, capped at 2 s. A focus return during that period joins it rather than reading a half-done switch, and every request queued meanwhile joins the one reread. An event on `current/` itself marks the watch failed, and the next focus regain watches the directory again. Each reread carries a generation and `finish` drops a result older than the latest one started; a result that changes nothing leaves the global untouched, so no observer runs and nothing is applied (`appearance::omarchy::tests`). Nothing is written under that directory.

Desktop rendering preferences and text factors are app-global inputs, while `GitTurtle` windows apply changed geometry to their own active and retained content. ## Ordinary history paging

`history_paging` keeps up to 5,000 rows and 64 MiB of commit/graph metadata in the visible window, plus at most one selected commit outside it. Older requests continue the same immutable traversal in 500-row pages; they never reread all previously loaded metadata. On reaching the window bound, Older advances to the next window while retaining the selected inspector/Compare identity. Previous navigates the captured ordering; returning to an earlier window rebuilds one pinned stream and discards bounded pages until its offset. Latest and Show latest explicitly capture current local tips and return to row zero without selecting a different commit. This backward restore is linear in depth; there is no permanent 10,000-row ceiling and no full-history metadata cache.

A page refused or failed leaves paging as it was before the request: its scope, offsets and selection. A cold tab's restore reads its saved page in its saved scope, which the window takes only with that page's rows (`request_history_page_in`); refused, as while a write runs or with no repository, or failed, as where the saved scope's commit is gone, the page leaves paging on the scope the snapshot shows, so the next Older or Previous continues the history the window lists. Read, a page in another scope replaces the window whatever its offset; only a page in the window's own scope continues it, since one appended where its offset followed the snapshot's rows joined two histories at a seam that skipped or repeated commits. Each page read sets its scope after `request`, which ends any earlier read's, and only that read's landing page takes it, so a page compares only its own read's scope: a read that replaces it, fails or is dropped (`request`), and a search or tab switch that takes paging over (`history_paging::State::take_settled`), clear it, and a read ended otherwise (`invalidate_read`, a bare generation bump) leaves it set, harmless, until the next page read sets it again, as no page of that read lands. Pinned as the page was asked for, the saved scope stayed under the snapshot's rows, and Older read that scope's next page there, skipping commits or failing on every press (`repository_tabs::tests::a_restores_unread_page_leaves_paging_on_the_shown_history`).

A page asked for at or past the end of its scope's history never shows an empty window while the scope has commits. The worker answers a position past the end with the empty page at the end, which tells the window where the history ends; the window then reads the last page's worth of rows up to that end in the same scope, 500 rows ending at the oldest commit, or the newest page where the history is shorter than a page, and a restore goes on from it to its saved selection, selecting the saved commit where that page lists it (`receive_history_page`). Older reaching the end of the window's own history is the one empty page that keeps the window, and it ends Older. The empty page at the end once emptied History's window, and a page past it failed the restore's read and left the snapshot's rows under an error (`repository_tabs::tests::a_restores_page_past_the_end_shows_the_last_page`). Reading that last page replays the captured stream again, linear in its depth like Previous; it happens only when a saved position no longer exists. A saved scope is an immutable set of commits, so no rewrite or branch reset shortens its history; a fetch at a shallower depth does, or a session file edited by hand, and the last page that exists then shows. A later write that the follow-up read meets ends a restore there with the snapshot's rows (`repository_tabs::tests::a_restore_with_no_page_to_read_ends_and_opens_the_held_search`).

The worker owns one `HistoryTraversal` and `GraphCursor`. Incremental graph preparation preserves frontier lanes/colors across page and window boundaries, commits cursor state only after cancellation checks, and latches an honest node-only fallback if its lane/edge allowance is exceeded. The graph column has a bounded automatic viewport (25% of the history width, between 112 and 280 points, while honoring larger saved widths); shared horizontal lane navigation preserves actual spacing without allowing offscreen ancestry to push commit messages away.

Search retains/restores ordinary paging state. `history_updates` keeps a bounded, per-worktree observation separately from the paging cursor and selected inspector. Quiet refresh follows row zero only in ordinary History at the top; Compare, Working Changes, older rows, deep windows and search retain their exact history, selection and content. History's scope toolbar cues a pending update the list does not show, without a row of its own (`GitTurtle::history_update_cue`): its words beside the count where they fit, a polite status, and an accent dot on Latest, whose name and tooltip lead with the cue and which reads current local tips and ends it. A quiet read that History follows installs the rows at the top and ends the cue (`history_updates::State::observe`), so the reads after a Pull or Push from History's top end it; one read elsewhere adds to it. The shared update row it replaced, above every mode, offered Show latest and Dismiss and pushed the page down 35 px; Compare and Working Changes now show the cue when Back or History returns to the list. The Latest control always reads current local tips, including when the visible window starts at zero. Explicit actions leave a captured search; passive reads preserve both its results and its normal-history return context.

New counts are exact only for complete histories within one 500-row page, or a bounded single-parent chain that proves extension of one previous tip. Merges outside complete coverage, removed refs, rewrites and page-limit uncertainty say History updated. Repeated changes coalesce; unchanged observations do not repeat a notice. Repository tabs retain their own observations and commit receipts; opening a scope resets its observation. Successful commits retain an explicit View commit receipt, resolved from the returned OID through a bounded worker read. That action selects the actual commit while leaving a subsequent composer draft saved. Passive updates never select a different commit or enter Compare. `history_page_frame_ms` measures the page handler through its next frame callback, excluding pre-handler input dispatch, OS presentation and completed GPU work. Worker elapsed time remains a separate metric.

## Search and retained inspections

Repository-wide search pins scope tips across pages, shares the replaceable read worker, and propagates cancellation to the core history process. Retain the ordinary history separately and restore it on clearing search. Foreground commit/file activation pauses search without discarding its results or cursor. Keep Restart explicit so users can search new commits/current tips after a write while quiet refresh preserves the captured search. An explicit History Refresh also restarts scope. Distinguish exhaustion from page, scan, time, byte, and UI-retention bounds; never present a bounded partial scan as an exhaustive no-match result.

File history uses an explicit path and immutable anchor, preserves rename paths/absent sides, and restores the preceding repository context on Back. Its first-parent lineage and pagination limits stay visible. Attribution and line history also use bounded worker reads and check repository, target and selection generations. Attribution owns a separate accessibility focus handle. Nested inspections restore the preceding comparison and line selection; explicit repository/scope/write transitions unwind them.

Return contexts retain conflict views and subscriptions alongside text editors, including draft cursor state. Returning to an interrupted Quick source load reissues `TrackedPreview` with its captured scope and byte-safe path. Absent comparison sides and unavailable working-file history anchors never fall back to the normal history selection. Closing the last retained inspection resumes queued passive refresh after the current handler finishes.

Changed-file path filtering shares cached row identities with renderers. `path_filter` normalizes old/new paths and matches queries on a lazy serial background lane, with cancellation checkpoints and explicit 100,000-path, 16 MiB index, 64 KiB single-path and 4,096-byte query limits. Replacements call `refresh_file_filter`; clears reset its state. Generation and file-snapshot identity checks reject stale replies, and a matching reply clears a selected preview only if that file is hidden. While a History or Compare query is pending the list keeps the rows the last reply left, files of the same snapshot that stay actionable, so typing never draws an empty list or a false "No matches"; "Filtering changed paths…" shows only for a snapshot with no rows yet (`path_filter::tests::typing_a_filter_keeps_its_rows_until_the_answer_lands`, and for Compare and Working Changes `compare_and_working_filters_keep_their_rows_until_the_answer_lands`, where an older query's job, released first, answers as superseded and leaves the rows as they were). History's queries coalesce: one job runs in the lane, and the newest query typed meanwhile waits for its answer, replacing any that waited before it, so typing faster than the worker answers never fills the lane's queue and is never refused as busy (`twenty_keys_typed_while_the_worker_runs_coalesce_to_the_last_query`). Rendering does not scan or lowercase paths. New revision inspections start with an empty path query; Back restores the preceding query, text review options and editor entities. Working Changes shares this executor and normalization code: status snapshots are shared through `Arc`, directory grouping and matching run off the UI thread, and refreshed entries cancel the previous index. While a result is pending the list keeps drawing the previous result's rows and counts, so it neither empties nor moves: they are drawn only, and selection, keys, copying, menus and row departures see no rows until the new ones land (`actionable_working_rows`), with selection actions disabled. Rows kept across a status with other entries index the earlier status, which `FilterState::supersede` keeps with the cursor among them until the new rows land; a retained tab keeps rows only with their own status and counts. "Filtering working paths…" shows only before a list's first rows. A query that matches nothing leaves the list only its two empty headings; the list draws `working-no-match` in their place, an `EmptyState` with Clear filter (`clear_working_filter`), decided from the shown rows (`working_no_match`) so it stays while a newer query's rows are prepared, with a floor that keeps it whole (`working_no_match_floor`) and none of the selection controls above the list changing height. Accepted results reconcile literal path/area identities and quiet-refresh scroll anchors. Counts and conflict summaries are prepared with the rows. Filtering never narrows the meaning of Stage all or Unstage all: those actions are disabled while a query is present.

Working Changes previews use their own status-path filter. The retained History
path query never filters a working preview, including quiet refresh results;
returning to History reapplies that query to the retained changed-file list.
Superseded History filter replies cannot clear a Working Changes selection.

## Local refresh

Filesystem callbacks only enqueue bounded local events. Resolve actual private/common Git directories and register watchers outside the UI thread; do not poll repository trees or invoke Git in the callback. Coalesce bursts, ignore passive access/lock noise, and defer quiet reads behind active previews, search, file-history inspections, status work or writes. A quiet read deferred behind a write or a review's preparation, in the shown repository or another tab's, starts as it ends (`read_deferred_working` calls `try_automatic_refresh` last), or as the working read that end asked for lands; a tab restored during a Fetch in another, with no watch registered behind it, once kept its history and rows until something else read them (`page_navigation::tests::a_quiet_refresh_held_back_by_a_write_runs_as_it_ends`). One that attribution, file history or a revision comparison holds back starts as that closes, attribution's close included, and until then Changes with no status shown does not count it as reading (`GitTurtle::quiet_read_reads_working`): with attribution open, its status read failed, it once said "Reading the working tree…" for as long as attribution stayed open, and the close read nothing until another change was reported (`page_navigation::tests::a_quiet_read_attribution_holds_back_waits_for_it_to_close`). Preserve refresh epochs and selection/status generations so superseded results cannot apply.

Quiet snapshots update local metadata without navigating away, clearing search, or replacing an unchanged immutable preview. The quiet read a write asks for as it ends (`refresh_after_write`) carries `LocalChange::after_write`, which the watcher never sets: until the read that carries it lands, menus refuse writes as while the write ran (`GitTurtle::write_unsettled`, folded into `native_accessibility::MenuInputs`), so none is built for the state the write left behind, and a file saved outside the app dims nothing. A write that changes only the working state (Stage, Unstage, Discard, Ignore, Delete untracked file…, Resolve, a stash's recovery) reads the status again as it ends rather than asking for a quiet reload, and menus wait for that read to land as well (`GitTurtle::status_after_write`, the `work_generation` it was asked at). A read that replaces it (`refresh_worktree`), as Refresh or showing Working Changes starts one, takes that mark with it, so menus wait for the new read instead; replaced unmarked, the write's read was no longer counted, and a Working row's open menu was built again from the status the write had just changed before either read landed. A reload that another page or an open inspection holds off (`GitTurtle::quiet_reads_held`: Settings or the hub, File history, a revision inspection or Blame) refuses nothing until it can run, as the window returns to the repository or the inspection closes and starts it; returning through the repository's own tab (`switch_repository_tab`, from the tab strip, the tab menu, its shortcut or opening the project again) starts it as Back does, where it once waited for the next local change with every menu refused, and closing Blame starts it on the next frame, as closing File history does. Refresh changed mutable editors in place and retain manual conflict drafts by conflict identity. A vanished scope keeps the displayed history with an explanation, reported once: after it is dismissed, later quiet refreshes and accepted writes do not raise the same vanished scope again until a snapshot resolves a scope. An explicit Refresh (or Show latest, or a restored tab) resolves the branch or worktree scope again; when it is gone the worker reads All history instead, and the page lists the repository's commits with one polite status naming the vanished scope, never "Could not open repository" or an unavailable tab. That status wraps to as many lines as its text needs beside its Dismiss action, so a long branch name or worktree path is read whole at every interface text size. An unpinned History search that finds its scope gone reports the scope change rather than a failed read. Partial coverage remains visible through a quiet footer status with Refresh and copyable Details; it is separate from Git operation failures and clears when coverage recovers. Neither a filesystem event nor focus regain may trigger a write or network action.

Linux registers essential private/common Git roots and refs before bounded working-tree coverage. Core prepares byte-safe tracked-path ancestors and Git ignore matchers (nested `.gitignore`, common `info/exclude`, and effective global excludes); ignored trees are pruned, while tracked paths inside ignored directories remain covered. Directory symlinks are not traversed. Missing/replaced directories during enumeration are ordinary races, not watcher failures. Existing metadata watches survive permission, OS-watch, directory-count, or scan-budget constraints. Native recursive subscriptions remain in use on other platforms.

Directory creation and renames add only the affected subtree. Coalesced index events update tracked ancestors; ignore edits reconsider the affected subtree, and external excludes/config changes reconsider coverage. Lost events allow one bounded reconciliation per continuous burst. Scans stop at 16,384 registrations, 200,000 entries, or two seconds; at most 256 omitted roots are retained. Freed registrations retry omitted roots once, while explicit Refresh or focus regain can reconnect degraded coverage. Ordinary quiet reads do not repeatedly rebuild an unchanged degraded watcher. No timer polls the tree. Core watch policy bounds tracked paths to 100,000 and source path/rule bytes to 16 MiB, with a 1 MiB individual ignore-file bound; Git subprocesses retain their existing passive deadlines and output limits.

## Retained commit messages

The inspection's `inspector_message` belongs with the existing
`file_history::ReturnContext`, including nested File History and warm tabs. File
activation and Compare/Back keep its OID and viewport. Selecting a different OID
invalidates its display pieces and starts at the beginning; replacing a
repository or closing its tab releases them. Projects/Settings remove the view
without discarding its state. Cold restoration deliberately starts the message
at the top, rather than persisting a second copy of commit text. Copy callbacks
revalidate the displayed OID against the current loaded selection.

## Repository tabs

`repository_tabs.rs` owns canonical worktree tab identity, saved bookmarks, and retained `ReturnContext` chains. Each window has one active repository reader/watcher; switching invalidates pending reads, drops the branch comparison Merge… or Rebase… asked for and ends its busy state with it (`cancel_integration_comparison`; dropped alone, "Comparing branch tips…" once stayed for good and held every later write and working read, `page_navigation::tests::a_tab_switch_ends_the_branch_comparison_it_drops`), releases its history stream off the UI thread, pauses PDF/model/Markdown work throughout retained contexts, freezes GIF playback, and restores the new tab before a passive rescan. A selected immutable commit can remain outside the visible history window. Opening aliases deduplicates after core discovery; linked worktrees retain separate tabs and drafts.
