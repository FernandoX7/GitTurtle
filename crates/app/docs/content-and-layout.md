# Content and layout contracts

Read this when changing or reviewing themes, geometry, content preparation, editor behavior, images or cache accounting. Source ownership is mapped in [app guidance](../AGENTS.md); visual intent is in [design](../../../DESIGN.md).

## Theme and retained layout

Use semantic appearance colors for native controls and custom content together. GPUI Kit 0.6 reads component backgrounds from resolved `ThemeTokens` and foregrounds from `ThemeColor`; after overriding colors, rebuild `theme.tokens` before `Theme::sync_base`. Updating only the app palette leaves native controls stale. Theme changes invalidate concrete editor decorations without rereading immutable content or eagerly rebuilding hidden editors. A theme switch submits no worker job and keeps the retained patch and split editors and the patch editor's Find query and matches (`settings::theme_apply_tests`, which clicks real Settings theme cards). Under `GITTURTLE_TRACE` it prints [`gitturtle.theme_apply_frame_ms`](../../../docs/benchmarks/metrics.md), from `choose_theme` entry, for a built-in or a custom `ThemeSelection`, to the next frame callback; the [first release baseline](../../../docs/benchmarks/2026-09-18-theme-apply.md) is the reference the theme editor and picker work measures against. The theme editor's live preview uses the same path: `theme_editor::State::preview` holds the open draft, `apply_appearance` applies it in place of the saved selection, and the first edit of a frame applies in its handler while later edits in the same frame coalesce to one application at the next frame callback. Its own metric, [`gitturtle.theme_edit_frame_ms`](../../../docs/benchmarks/metrics.md), is stamped at entry to the token row's change handler before the value is parsed (or at `open_theme_editor` entry), kept in `theme_editor::State` until the root render (`views.rs`) takes it into `GitTurtle::edit_trace_probe`, a zero-size element deferred above the dialog layer, and printed from that element's paint: the last thing drawn in the first frame after the handler, on the frame tick or in the synchronous draw `Window::dispatch_key_event` makes, so the value is the handler plus that whole draw and never a callback wait. It submits no worker job (`theme_editor::tests`); closing the editor drops the draft and re-applies the saved selection.

A palette application costs one whole-window layout, paint and present, so the path is built to ask for exactly one and to make it cheap. `apply_appearance` invalidates through its own `cx.notify()` and calls `appearance::sync_text_sizes`; it must not call `Window::refresh`, which marks the same window dirty but additionally bars GPUI's cached-view reuse for that frame. `appearance::apply_text_sizes` keeps that refresh for callers that own no entity to notify, where it is right: a text-size change moves every measured box. Reuse is what makes the Settings picker affordable. The rest of the frame is kept small by node count: the picker captions and the Your themes swatch strips are one painted element each (`settings::swatch_run`, the quads a row of divs painted), each card's miniature is one painted element too (`settings::paint_miniature`, which paints the boxes a div tree of its geometry would, through the same `paint_quad` snapping; it is not the earlier div tree redrawn but a miniature re-proportioned for the 132 px card, a 20 px top bar, 26 px sidebar and 10 px rows where the divs had 25, 30 and 14 px, beside a caption check badge as tall as the name's line, 15.6 px at the default size, where it was 18 px; so a frame that rebuilds every card under `Window::refresh`, as a click's release or a Tab's focus change does, lays out one node per miniature where a tree of forty stood), a token row of the editor lays out no spacer where no glyph is shown and no wrapper around its hex field (the kit `Input` takes the authored width and mono face through its own style refinement), a picker caption lays out the name row only on a card that shows the check badge or the warning glyph beside its name, and the Your themes rows are a `uniform_list` that keeps the kit focus ring's 3 px of room inside its own bounds (its content mask) and chains a wheel step to the Settings page only once the list has reached its end (`on_scroll_wheel` with `stop_propagation`, as nested scrolling behaves natively). That list is positioned absolutely over a flow box that is exactly the rows (`custom-themes-rows-box`), not laid out with negative margins: an absolute child does not enter taffy's sizing of the card, whereas a flow child whose margins pull its content contribution below its flex basis collapsed the card's content height under max-content sizing (taffy 0.13 scales that negative difference by the item's inner flex basis); `the_card_keeps_the_plain_stacks_geometry_around_the_rows` pins the card, the rows' box and the setting below for zero, one, two, eight and 32 themes. Because that content mask includes the ring's room, a row partly scrolled out of the viewport would paint into it: `render_custom_theme_rows` covers the room with two absolute strips of the card's surface, painted after the rows, while the rows stand off a row boundary, and leaves the room to a focused edge-slot action's ring on one; the boundary is judged where the list will stand after the frame's pending reveal, not where it stood (`settings::rows_off_boundary` resolves `reveal_focused_row`'s Nearest scroll as the list's prepaint will), so the frame that reveals a partly hidden row never draws a strip over its ring (`strips_cover_the_ring_room_while_the_rows_stand_off_a_boundary`). Every row's fill, the import highlight and the hover surface alike, is painted in one layer beneath all the rows rather than as each row's background, because a row paints after the row above it and its own fill would cover the ring's bottom edge around an action there (`a_focused_row_actions_ring_is_whole_beside_the_import_highlight`). The Settings page reveals the focused row too, with the ring's room from its own viewport's edge, placed where the list will stand once its own reveal lands (`settings::planned_rows_top`, which `rows_off_boundary` shares), so a row at the list's end against the status bar keeps its ring (`a_revealed_row_keeps_its_ring_inside_the_settings_page`). Each picker card, built-in or custom, shows a `settings::ThemePreviewBody` entity drawn with `Entity::cached` (by `settings::CardLayer`, beside the cached page; see [Cached Settings page](#cached-settings-page)), because a miniature draws its own theme's palette and a palette change does not alter a pixel of it; the card and the layer pin `text_color` to the previewed palette so the reuse key's inherited text style stays stable, and the caption stays outside the cached subtree because its selected badge and its warning glyph are drawn in the active palette, not the palette the card previews and the glyph may flag, and its background follows the card's hover state. The caption is at least 54 px (`min_h`), not exactly 54 px: at interface text sizes 11 and 12 its fixed padding, gaps, badge and swatches would otherwise squeeze the truncating name and description below their line height, so there the caption grows and the miniature gives up the difference (`the_caption_keeps_its_text_lines_at_small_interface_sizes`). The theme editor's preview card is the picker card's 132 px, so its miniature has the picker's proportions (`the_editor_preview_card_matches_a_picker_card`). The theme editor holds the same body beside its draft and pushes the draft in only when the palette really changed, so a frame that only renames, warns or moves focus reuses it too. A completed preference save asks for a frame only when it changed the status line or the error the page shows; otherwise every switch after the first would pay a second whole-window frame for nothing. `theme_editor::tests::an_edit_and_a_switch_each_draw_the_window_once` records the palette of every draw and asserts one draw per edit and per switch, none of them in the old palette and no draw from the save completion; the switch is a real click on the card, and because GPUI's click path calls `Window::refresh` on that mouse up, the test records the built-in and custom miniatures that release rebuilds and asserts the reuse on the edit frames instead, where every picker miniature, the edited theme's own included, is reused and only the draft's own is rebuilt. The Your themes card keeps its rows off every other frame's bill the same way History does: `settings::render_custom_theme_rows` is a `uniform_list` `min(rows, 8) × 30 px` tall, so a Settings or dialog frame lays out at most eight rows however many themes are saved. Its rows are drawn only in view, so their Edit…, Export… and Delete… (the kit's own tab stops) exist only while drawn; each row tracks one app-owned handle that is not a stop itself (`theme_editor::State::row_focus`) and its actions track app-owned stops (`State::action_focus`, through the kit `Button::track_focus` patch), so an action keeps focus while a wheel or scrollbar scroll takes its row wholly out of the list and the row comes back with it. A render finds the row holding focus through those handles and scrolls that row into view once per focus change, keyed by the focused action rather than the row, so a scroll away from the row stands while Tab onto another of its actions brings it back. While the focused action's row is not drawn the list tracks that action's handle, so the key still reaches the Settings key context, where `tab_theme_rows` scrolls the row back and the list's next render takes the step (`RowFocus::Step`) once the row's stops exist (`tab_after_a_wheel_step_scrolls_the_focused_row_back`, with the native frame 11 state's 63 px step); and `GitTurtle::tab_theme_rows` (bound to Tab and Shift-Tab in the Settings key context, ahead of the toolkit's Root binding) lets GPUI's own step stand whenever the row it should reach is drawn and otherwise scrolls the target row in, keeps focus where it was for that frame, and has the list's next render focus the action once the row's stops exist (`tab_walks_every_row_action_and_keeps_the_focused_row_in_view` and `tab_walks_the_last_rows_and_leaves_and_reenters_the_rows`, one walk in two halves so each fits the gate's twenty-seed rerun). Because the miniatures are retained, a card is paired with its body by lookup: each body is stored beside the `ThemeSelection` it draws in `GitTurtle::theme_previews` and found with `GitTurtle::theme_preview_body`, never by position, since `ThemeChoice::ALL` is in display order, `choice as usize` is declaration order and a custom id is not an index (`every_picker_card_draws_its_own_miniature` checks, from the rendered tree, that the body laid out inside each built-in card draws that card's palette; `custom_themes_form_a_third_picker_group` checks the custom cards the same way, with their "‹name› theme" names, the check on the selected card, the warning glyph on a palette with findings and the store write a click makes). `GitTurtle::set_custom_themes` is the only writer of `custom_themes` and keeps the custom bodies in step: a saved theme's body takes the new palette through `ThemePreviewBody::set_palette`, which notifies only when it changed, a new theme gets a body and a deleted theme's body is dropped, so a save invalidates only the saved theme's miniature. The frame that closes the editor is nonetheless drawn under `Window::refresh`, because the kit restores focus to the row's Edit… as it closes the dialog and `Window::focus` refreshes; `an_edit_and_a_switch_each_draw_the_window_once` records that rebuild beside the click's, asserts that only the saved theme's body was given a palette, and follows with a frame that reuses every miniature. The picker's warning glyph reads `theme_editor::State::warning_counts`, the per-palette cache the Your themes rows use, so a Settings frame recomputes no theme's readability findings; the picker grid is four columns at and above the 1,060 px breakpoint, three in the stacked layout and two in the narrow one, with 132 px cards, and a partial row's fillers carry the cards' padding and border so its cards stay on the full rows' columns (`picker_cards_keep_the_grid_geometry`). The guarded save notification and the missing refresh must not cost a result its frame either: `a_finished_transfer_and_a_confirmed_delete_draw_their_result` answers the native dialog across a window deactivation and reactivation, forces no draw afterwards, and asserts that the finished export, the finished import and the confirmed delete each draw the window with the notice or the updated list in it.

`Palette::readability_issues` (`src/appearance/custom.rs`) is the single readability rule set: the palette tests assert it is empty for every built-in, and the theme editor (`src/theme_editor.rs`) shows the same issues as warnings for custom palettes instead of adding its own checks. Each issue names the foreground token or graph lane, the background token or selected-row hover blend, the measured ratio and the minimum; the rows and thresholds are the [themes specification's rules table](../../../docs/development/themes/spec.md#readability-rules). `Palette::is_light` (canvas brighter than text) selects the graph lane set, so the lanes judged by the rules are the lanes painted.

Preserve list viewports using the ratio of each window’s pixel-snapped old/new row heights, including active and nested attribution/file-history lists and warm/cold repository tabs. Invalidate cached list dimensions after this adjustment so Working Changes does not reveal an offscreen selection over the retained viewport. When measured Working geometry changes during painting, defer its redraw until painting finishes; unchanged bounds must not schedule another frame.

retained repository tab, without saving new application text-size preferences.

### Cached Settings page

GPUI redraws from the window root on any notify and skips only views embedded with `Entity::cached`, so the Settings page is its own view. `GitTurtle` owns `settings_page: Entity<settings::SettingsPage>`, created in `GitTurtle::new` and dropped with the app; `GitTurtle::settings_page_element` embeds it cached, or uncached while `Window::is_a11y_active`, because GPUI records accessibility nodes only during prepaint. The page holds no state of its own beyond the last `PageKey` it built from. Its render upgrades a weak handle to the app and returns `GitTurtle::render_settings`, which reads the settings, the custom themes and the Your themes card state (transfer, notice, error, pending save, row scroll and focus), the operation error and busy state, the status line, the effective identity, the open repository and its project name, the four Settings inputs, the palette and the viewport. A keystroke or a caret blink in the theme editor's dialog notifies only the dialog and the app, so its frame replays the page.

Every site that changes what the page shows must reach it, through one of the paths below:

- `GitTurtle::notify_settings_page`, beside the site's own `cx.notify()`. It is called from `apply_appearance` (every palette application: a picker switch, a live-preview draft, its restore), `save_preferences` (every settings change and its refusal), the 32-theme bound error in `open_theme_editor`, the start and completion of an export and of an import, `tab_theme_rows` when the action holding focus has its row scrolled out of the list, `scroll_settings_page` (Page Up, Page Down, Home and End), `submit_custom_themes` (an editor save, an imported theme, a delete), `finish_custom_theme_save` (the store's answer) and, on Linux, `omarchy_changed` (a reread of the desktop's Omarchy theme that changed its card without applying a palette).
- The reconciler. The app's self-observer (`reconcile_settings_page`) compares `settings_page_key` (operation error, busy, status line, effective profile, repository path and project name) with the key the page last built from, and notifies the page on a difference. Other features, such as `workspace::write`, status replies and tab switches, write those fields and notify only the app.
- The input observers. `SettingsPage::new` observes the Default branch, external editor, identity name and identity email inputs, for typing, the caret, focus and selection.
- GPUI itself. Hover and press on a page control, a wheel step and a scrollbar drag notify the view they were painted in, which is the page. A click, a tooltip, `Window::focus` (Tab, and the reveal of a focused Your themes row), the switch between pointer and keyboard input, a dialog opening or closing, `repaint_page` on show and return, and a desktop text-scale change (`appearance::apply_text_sizes`) each refresh the window. A resize changes the page's bounds and so its cache key.

A missed notify leaves the page showing the previous frame's controls until something else rebuilds it: a Your themes card that stays disabled after its transfer ends, a list without the theme just imported, an error or status line that never appears, an input whose value or caret stands still. Because hover and press rebuild the page, the stale state tends to correct itself when the pointer moves. When a report shows that pattern, look for a missing notify before suspecting anything else.

Two elements keep the cache effective:

- `ViewNodeAnchor`. The toolkit's text element notifies its input state from `paint` on every frame. A notify issued during a draw dirties every view above the input's dispatch node at the next draw, so with the input's node inside the page, the page would rebuild on every frame. The anchors, prepainted after the page, register the four inputs' view nodes beside it instead. This relies on the pinned GPUI's `DispatchTree::set_view_id` keeping the last registration, and `set_view_id` is marked for removal upstream. Its regression check is the idle notify in `state_from_other_features_builds_the_page_through_the_reconciler`, which must replay the page.
- `CardSlots` and `CardLayer`. A cached view is rebuilt with `refreshing` set, which bars reuse for every cached view nested in it, so the picker cards' cached parts, built-in and custom, cannot sit inside the page: every live-preview edit rebuilds the page, and it would rebuild every card with it. Nor can the page issue their deferred draws: a replayed page copies its deferred draws without prepainting them, which leaves each cached view's prepaint range indexing an older frame, and GPUI then panics or grafts the wrong subtree. Instead, each card button holds the preview's rounded, canvas-colored box (its border transparent) around a `CardSlot` placeholder, which records its bounds, content mask and inherited text style while the page is prepainted, and a `CardProbe` beside it. `CardLayer`, beside the page, draws each card from those slots every frame as a deferred draw at priority 0 under the button's content mask. That puts the cards above every non-deferred part of the page and below dialogs, popovers and tooltips. `an_edit_and_a_switch_each_draw_the_window_once` and `an_edit_trace_ends_in_that_frames_paint_after_the_dialog` cover this path. Each card paints in the order its div tree did: the cached miniature (`ThemePreviewBody`), the caption's background, the cached card body (`ThemeCardBody`, below), and last the preview's 1 px hover ring, so the ring covers the miniature's top corners and anti-aliased edge. The caption's background and the ring follow the pointer, which is known only while the page paints (GPUI pushes group hitboxes during paint, after the frame's hit test): the probe's box turns its text style italic under the card group's hover and black under its press, the predicates the caption's `group_hover` and `group_active` styles used, and the probe stores what it reads for the layer, which paints later in the same frame. The box's own listeners notify the page on a hover change and refresh the window on a press, so the probe reads again whenever the state changes, and the cached body holds nothing that follows the pointer. While the ring is drawn the preview clipped its content inside it (`Style::overflow_mask`), so the layer prepaints and paints a hovered card's content under that clip, which is part of the cached views' reuse key; the probe's prepaint stores the state the paint is expected to read (before the paint the box's styles fall back to the hover and press its listeners recorded at the input, and a hover is not shown after keyboard input), so the frame that shows a hover change, a press or a switch prepaints the card under its clip. A paint that still finds the state changed, as a scroll under a resting pointer can, asks for one more frame (`Window::request_animation_frame`). `a_hovered_card_draws_its_miniature_under_its_border` asserts the paint order and the fill for rest, hover, press, selected and hovered, and after the pointer leaves; `pointer_input_on_a_picker_card_draws_one_frame` asserts that a hover, a press and a switch each draw one frame that asks for no other and build no card body or miniature twice.

### Cached picker card bodies

A live-preview edit builds the page again but replays the picker's card bodies. The app owns one `settings::ThemeCardBody` per built-in and per saved custom theme in `GitTurtle::theme_card_bodies`, created beside the card's miniature in `GitTurtle::new` and kept in step with `custom_themes` by `set_custom_themes`; it is found by selection (`theme_card_body`), as the miniature is. It renders from its own state and reads no other entity: its `settings::CardKey` (the card's own palette, name, description and warning count; the applied accent, accent foreground and canvas only on the selected card, which draws the check badge and its ring; the applied warning and canvas colors only on a card with findings, which draws the glyph) and the applied palette those tokens come from. Its miniature box is empty: `CardLayer` draws the miniature, a separate cached view, at the box's bounds, so a switch that rebuilds a body still replays its miniature. A body is built again only when its key changes, so a live-preview edit rebuilds none unless it edits the accent tokens or the canvas color (the selected card) or the warning or canvas color (the cards with findings), and a switch rebuilds the two cards whose badge moved and the cards with findings.

`GitTurtle::sync_theme_cards` sets every key from the app's state, and `ThemeCardBody::set_key` notifies only on a change. It is called from:

- The app's self-observer, on every app notification while Settings is shown. Every change to a key's inputs notifies the app (`apply_appearance`, `choose_theme`, `set_custom_themes` and the saves, imports and deletes around it), and the observer runs before the frame that shows the change, so that frame builds the body through its cached path.
- `SettingsPage::render`, on every build of the page, as a safety net: a notify issued during a draw is kept for the next frame, so a key this sync corrects is shown one frame late.
- GPUI itself: `Window::refresh` (a press, a click's release, focus changes, a text-size change) rebuilds every body, and a scroll or resize changes a body's bounds, so its reuse key.

A missed key change leaves a card showing a previous caption: the old name or description, a check badge on the card no longer applied, a badge or glyph in the previous palette. `a_switch_builds_the_two_card_bodies_whose_badge_moved` fails if the self-observer's sync is removed: it draws single frames and asserts that the frame that rebuilds the page builds the two bodies. `a_live_preview_edit_replays_the_card_bodies_it_leaves_alone` asserts that a canvas edit and an accent edit each build the selected card's body alone. The existing picker tests (`custom_themes_form_a_third_picker_group`, `every_picker_card_draws_its_own_miniature`) read the badge, glyph and names the bodies draw. `settings::page_shows` runs pending work before its refreshed frame, since a later frame that replays a body records none of the body's debug bounds.

The self-observer computes every card's key on each app notification while Settings is shown, beside `settings_page_key`: 52 small keys with the 32-theme store, which clone the names and format the custom descriptions. Its cost has not been measured.

### Cached token rows

A keystroke or a caret blink in the theme editor builds one token row, not the dialog's twenty-one. Each `theme_editor::TokenRow` holds a `TokenRowView` entity, created in `ThemeForm::new` and dropped with the form; the form owns the row's state (hex field, color picker, validity) and the view keeps only the last `RowKey` it built from. Its render upgrades a weak handle to the form and returns `ThemeForm::render_row`, which reads the draft color, the row's validity, its readability flag, the pending save, the applied palette, the rem size and the picker's focus. `ThemeForm::row_element` embeds the row with `Entity::cached` (a 30 px slot the width of the column), or uncached while `Window::is_a11y_active`. The form itself is not cached: it renders on every frame the app does. A row is built again in three ways:

- The key. `ThemeForm::row_element` compares `ThemeForm::row_key` with the key the row last built from and embeds a changed row uncached for that frame, so every form-side change (an edit, a validity change, a readability flag, a pending save, a palette application, a text-size change, the picker's focus) builds it with no notify site to miss. The next frame embeds it cached again, which builds it once more because the cached element has no state yet.
- The row's observers of its hex field and its color picker (`TokenRowView::new`). The form registers each hex field's view node after its rows with `settings::ViewNodeAnchor`, as the page does for its inputs, so the kit input's notify from paint on every frame dirties the field, the form and the app but not the row; typing, the caret, selection and a picker's popover reach the row through these observers.
- GPUI itself: hover, press and focus refresh the window, and a scroll or resize changes the row's bounds and so its cache key.

A missed rebuild leaves a row showing a previous frame: a hex field whose text or caret stands still, a swatch or glyph that does not follow the draft. `a_hex_keystroke_builds_its_row_and_replays_the_others` fails when the anchors or the hex observer are removed (every row, or no row, would be built for a keystroke and a caret blink) and asserts that a picker notification builds its row alone and an idle frame replays every row; `invalid_values_names_and_readability_warnings` covers the key's validity path. Tests read row selectors through `settings::page_shows` for the same reason as page selectors.

## Commit-message inspector

`commit_message::State` retains a selected immutable OID, shared display pieces,
variable-height `ListState`, and keyboard focus. History/Compare allocate at most
45% of the inspector to this message region; its copy toolbar remains outside
the scroll viewport. File History shares the presentation inside the remaining
height between its bounded header and footer, leaving revision rows usable.
Reading order is title, available body, then author/date/parent/path metadata.
Empty bodies add neither filler nor a blank clipboard suffix.

Preparing a newly displayed OID partitions the already-loaded model once; paints
clone only shared pieces. Each text-shaping input is at most 1 KiB and 16 source
newlines. Pieces prefer source lines, whitespace and grapheme boundaries; an
individual grapheme exceeding 1 KiB continues at a UTF-8 boundary to keep shaping
bounded. No source scalars are dropped. Copy reads the complete loaded title/body
only on explicit activation and is independent of presentation segmentation.
Navigation row labels are bounded summaries; they do not shape or announce a
megabyte title. The inspector never creates an editor or starts a Git read.

The variable list owns measured row geometry and remeasures proportionally when
interface scale changes. Text and list reservations count toward retained-tab
admission, including nested return contexts. Keyboard arrows, Page Up/Down and
Home/End scroll the focused message; labelled native buttons provide message
and hash copy. They are `copy_feedback` copy buttons, each a copy icon before
its label and as wide as the wider of its content and its copied content (check
and "Copied"), which for Hash is the copied content; both contents start at the
button's leading inset, so the check replaces the icon in place. Where Copy
message does not fit a row of its own, both are compact 28 px icon squares on
one row. `Toolbar::within` measures them, with History's and Compare's
Actions, at the width the inspector is drawn at (`drawn_inspector_width`): the
panel group's size within the inspector's range, which a window resize
rescales and a drag sets, rather than the saved width, so no control wraps
below the row it was fitted to, and where the window fixes the inspector's
width the reserved rows match what they draw. It measures on whole device
pixels, as the layout draws them: the inspector's edges at the nearest and
each control's width rounded up, since at 18 pt Actions once wrapped below
Hash in a 455.4 px inspector its unrounded widths fitted by 0.05 px. The range
ends where the content column's minimum leaves no more room, so the inspector
never runs past the window. Working Changes lays its inspector out at the same
width. Only a drag writes the inspector's width, within that range at the
window's width and interface size then (`bounded_inspector_width`). A restore
at startup or of a tab, a narrower window and a larger interface size draw a
saved width within the range without writing it, so a half tile or a tab shown
there never overwrites the width chosen in a wider window; the store's own
280–480 px bounds still apply when it loads. The width walk starts History and
Working Changes from the widest saved width as well.
Native platform quality remains a separate validation requirement.

The pieces and the selectable metadata lines (author, date and short hash, or a
revision's lines) form one text document (`commit_message::selection`). The
presentation owns one base `TextSelection` participant registered for the whole
viewport, so the window layer's drag, auto-scroll, multi-click and clearing apply
while pieces enter and leave the list. Its endpoints are content keys holding
document byte offsets, resolved against the runs the previous frame painted;
each piece records its offset in the full message. While a drag is held, each
paint resolves the cursor again at the pointer, so a drag that auto-scrolls and
is released without moving ends at the text then under it. Painting a run intersects one
range, and copy slices the retained pieces between the offsets only on Copy,
restoring the newlines between runs: a boundary's stripped newline, the blank
line before the body and the breaks before and between metadata lines. Select
All selects the message alone, so it copies exactly what **Copy message** does.
Replacing the presentation (a new OID) or taking it into a return context or
warm tab (`State::select`, `replace`, `take`) ends its selection at once, though
the window keeps the participant until its next frame, and releases the shaped
runs it and the participant kept; a click elsewhere clears the selection but
keeps the runs, from which the same press resolves its new anchor. The highlight is the applied theme's fitted text selection
(`EditorHighlights::selection`). A non-empty message selection wins over a
focused list's Copy Selected List Item, which otherwise copies the History
row's full hash or the changed file's path.

## Working row travel

A file row's own Stage or Unstage (its control or its menu item) records where the row stands in the window, from the list's last viewport, scroll offset and snapped row height, before the write is submitted (`GitTurtle::depart_working_row`, `motion::RowTravel::Departed`); under reduced motion nothing is recorded. The departure names its repository, path and group. The path filter's worker finds where the rows the write produced put it (`motion::landing`, beside `rows`): only a path that left its group and stands in the other has landed, so a failed write, or a file edited again, moves nothing. Until they are installed the list keeps drawing the rows as they were (`FilterState::supersede`), so in those frames the row stays where the user left it and nothing above it moves. When those rows are installed the flight starts on the executor's clock, with a 150 ms timer that ends it and draws the row in its slot (`land_working_row`). A departure that did not land is dropped at the first installed rows after its write finished, or at an unchanged status while no rows are being prepared (rows still prepared for an earlier status, as when a quiet refresh follows the write's own read, may yet land it), and on a status error or a tab switch, so a later refresh never moves the row; a flight ends when the list is rebuilt (`interrupt_working_travel`). While a flight is drawn the list keeps the landing index as an empty slot (`motion::slot`), a canvas that records its bounds and the list's clip while the list is prepainted, after any scroll the list applied in that frame, and the list's row builder records the place of each section heading it builds in that frame (`motion::Slot::heading`); `motion::TravellingRow`, the pane's next child, lays the row out at that slot's size and draws it from its departure towards the slot on an ease-out curve, above the rows it passes, under that clip less the bands of those headings (`motion::uncovered`; every row is the slot's height, so a heading `n` rows from the slot lies `n` slot heights from it), so a heading stays whole and on top while the row passes beneath it, and asks for another frame only while it draws. The list's layout is final in the first frame, every other row takes its place at once, and a slot outside the viewport draws nothing. `motion::tests` cover both directions on the test clock (the first frame where the row was left, the eased midpoint, the slot a frame before the end and at 150 ms), every frame of both directions' flights at 13 and 18 pt, also past a heading the list's top or bottom edge cuts and with Directories on, in which each heading drawn paints what it paints at rest and the row, told from a row in the same place by the band it is masked to, shows all of itself inside the list and under no heading, the first frame under reduced motion, a failed Stage followed by an outside change, which moves the row at once, and a filtered list that keeps every row in place while the filter's worker is held, its row still landing after another read of the same status meanwhile. An accepted press of a row's control also records the pointer and the pressed row (`GitTurtle::hold_still_pointer`, `motion::StillPointer`); when the installed rows no longer put that row in its place (`rows_moved_under_pointer`), the rows draw no hover, the row controls and heading actions take `appearance::still_control_button_variant`, which has no hover fill, and attach no tooltip, not even a confirmed control's word (`copy_feedback::still_feedback_button`), until a mouse move to another position over the list ends it (`pointer_moved`; a frame's synthetic move at the same place does not). At that moment, while the pointer still rests where it pressed, the window's tooltip is hidden too (`gpui_kit::component::Root::hide_tooltip`): the kit keeps a tooltip a control asked for, shown or waiting out its delay, until that control's hover ends, which a control no longer drawn never reports, so the pressed control's "Stage gamma.txt" showed over the row that took its place about a second after the press. A pointer that has left that place, as onto a control outside the list whose moves the list does not see, ends the still state there instead, and the control it rests on keeps its tooltip.

## Images and cache accounting

Prepare render-image pixels on the worker. Before/After image sides share bounded pan state; active drags continue across app content and clear on release or preview replacement. Overlay/wipe composes existing images in one source coordinate system without copying pixels on drag. Preserve absent/error sides, original dimension ratios when sides are independently downsampled, and the distinction between source dimensions and decoded-preview zoom. Retained navigation copies exclude active drag gestures.

An image comparison's accessibility tree keeps its shape as the room changes ([native accessibility](../../../docs/native-accessibility.md)). The captions and a click's band are groups in every layout, named and described only where they carry the words that gave way, because GPUI writes a node only for an element with a role and a container that takes one only in some layouts moves what it holds under a new node. Exactly one drawn node carries those words: the image's node where the image is drawn, otherwise the band, otherwise the captions. The image's node holds only the canvases; a side's reason lies over it as its sibling. Tests read where GPUI puts such a node by wrapping its element in `native_accessibility::recorded`.

GIF comparisons start paused and retain a bounded set of worker-prepared frames.
Play/Pause and frame stepping share one time position across Before/After; a
shorter side holds its last frame until both loop. Painting selects an existing
BGRA frame and requests the next native frame only for active playback in an
active window. Hidden and paused canvases schedule no animation loop; retained
navigation clones freeze playback. Cache accounting includes every frame,
timeline metadata, first-frame RGBA and captured compressed bytes. The static
`decode_image` API and secondary static image surfaces still show frame one.

The preview cache counts retained source buffers, patch metadata and CPU image allocations. UI-held `Arc`s, editors and GPU textures may outlive eviction; its budget is not a total-memory cap. Changes to `Content` must keep `Content::bytes` accurate.

Register every directly painted `RenderImage` with `image_lifetime`, including
static dialog/model/PDF surfaces and every GIF frame's shared image. The global
registry owns one cleanup reference and retires all atlas frames through GPUI's
`App::drop_image` only when no cache, view, retained inspection or canvas owns
another reference. Every real workspace render schedules one coalesced check
after its frame/element cleanup, including Back and Projects with no new image;
window close also checks after its entities are released. Sweeps never schedule
themselves or keep idle animation demand alive. Dropping CPU pixels alone does
not remove the pinned renderer's atlas tiles.

Dialog children use the generic `rich_preview::render_comparison` helper with owned preview data and a weak owner handle. Rendering must not read or update the parent `GitTurtle` entity while its dialog layer is rendering; that reenters GPUI's active entity borrow. Parent updates belong in explicit action callbacks, and PDF page changes notify the rendering child.

Opt-in `GITTURTLE_TRACE` records new registered preview images, completed
`App::drop_image` retirement counts (including all GIF frames), retained image
counts, and the count after window closure. It emits only lifecycle events and
does not schedule draws or polling. This proves application retirement calls;
it is not a measurement of Metal driver allocation bytes. Pair native repeat
cycles with process/resource observations when evaluating preview cleanup.

## Captured documents

`rich_preview` owns shared comparison presentation and static metadata/page surfaces. Interactive PDF navigation belongs to `pdf_view`: initial preparation uses the repository worker; later pages use a separate serialized render lane and bounded per-side page/text cache. `model_view` retains decoded geometry and uses one active render with one replaceable pending pair. Hidden or retained views cancel pending work and schedule no idle frames. Their generation checks, retained-memory reservations and `image_lifetime` registration must follow the content into tabs and nested inspections.

GLB appearance and deformation data stay immutable and share their texture and
animation storage with evaluated frames. The model worker evaluates the requested
pose, rasterizes, and converts pixels before publishing the current generation.
Each side chooses a clip or Default pose; both use one comparison clock in seconds.
The shorter clip holds its endpoint until the longest loops. Playback requests at
most 30 samples per second at 360 pixels, skips elapsed samples while a frame is
pending, and uses 720 pixels for paused inspection. No frame history is cached.
Clip changes, scrubbing, lifecycle pauses and failures stop both clocks together;
hidden views invalidate their work, including stash preview replacement/closure.
Reduce Motion disables Play and leaves clip selection, scrubbing and stepping
available. A paused comparison never resumes automatically.

Playback preserves the camera. Fit uses the displayed poses' bounds (their union
for linked cameras); Reset restores the initial authored comparison framing.
The timeline and per-side displayed-pose time distinguish requested comparison
time from the last completed frame. Appearance labels distinguish unlit rendering,
base-color inspection and geometry-only output; bounded details explain omitted
appearance resources and unsupported clips. Source bytes remain independent on
each side and never become a rendering-resource resolver.

`markdown_view` prepares native blocks and captured local resources off the UI thread. Resource reads use core's explicit revision/index/working scope and byte-safe resolver. Remote images and arbitrary URL schemes are refused; HTTP/HTTPS navigation requires an explicit browser action. Keep exact source/diff available; rendered documents, diagrams, PDF text and model frames never become staging input. PDF and decoded-encoding views never acquire partial staging actions. Consult the [document preview contract](../../../docs/document-previews.md) and [interactive 3D contract](../../../docs/interactive-3d.md) for finite format support, external-resource restrictions and separate input/output bounds.

Before/After retain independent captured identities and absent sides; Quick Open uses a single Source side. System Quick Look on macOS, or on Linux the desktop's default application for a passive type decided from content on the worker (`src/system_preview.rs`), receives an explicit, private, read-only copy of captured bytes with a safe suffix, never a substituted working path. Images also retain captured bytes and optional literal SVG source for system inspection/copy, counted in the cache. The [file support matrix](../../../docs/file-previews.md) owns codec, encoding and external-viewer limits.
