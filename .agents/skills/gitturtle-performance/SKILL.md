# GitTurtle performance and passive reads

Use this workflow for the affected hot path. Start with the relevant code and existing evidence in [architecture](../../../docs/architecture.md) and [validation](../../../docs/validation.md); do not turn an ordinary change into an exhaustive audit.

Trace an interaction from selection through metadata, file list, selected-file content, and presentation. Preserve that order; expensive rename detection, aggregate statistics, syntax parsing, or unrelated blobs must not gate the first useful view.

In History, finish the changed-file list without eagerly preparing a preview. Enter Compare only on file activation. Back uses retained history and must not wait for an active preview; a late result may populate content but cannot switch modes or build an editor while hidden. Measure commit-file-list and file-preview frames separately.

Keep logical selection separate from rendered rows. Virtualizing a list must not break offscreen selection/copy, keyboard navigation, or graph continuity. Keep graph topology, patch gutter/decorations, and render-image pixel preparation on the worker; editor constructors consume prepared results. See [app contracts](../../../crates/app/AGENTS.md) for the relevant symbols.

For page or menu performance, inspect the construction boundary: `views::render_repository` is called only for the Repository page, so Projects and Settings do not construct hidden history, inspectors, or previews. The branch-switch menu in `workspace::render_git_actions` builds bounded choices when opened; keep the full branch set searchable without constructing every menu item on each frame.

Inspect `worker::PreviewKey`, `PreviewCache` limits, and `Content::bytes` when changing previews. Count retained buffers, patch metadata, and decoded CPU images. Separately inspect UI-held references, editor copies, and GPU texture lifetimes: the cache budget is not a process-memory cap. Compressed image size is not its allocation cost.

For retained documents and repository tabs, follow [document preview bounds](../../../docs/document-previews.md), [image ownership](../../../crates/app/docs/content-and-layout.md#images-and-cache-accounting), and [tab lifetimes](../../../crates/app/docs/navigation-and-refresh.md#repository-tabs). PDF page rendering, model camera rendering, and Markdown link preparation have separate bounded lanes; the main worker's queue does not bound them. Account for demand-loaded PDF pages, model geometry/frames, captured Markdown assets, and all GIF frames. Trace pause/cancellation through nested retained contexts when leaving a page or switching tabs. Idle or hidden views must not sustain animation frames. `image_lifetime` retires atlas frames after the final content owner releases them; CPU/cache eviction alone does not establish GPU cleanup.

Review `Worker::submit`, `Cancellation`, and `execute` at the worker boundary. A generation check only discards stale output; verify queued work is replaced or cancelled and concurrency remains bounded. History search, file history, blame, and line history propagate `HistoryCancellation` to the active core operation; decoder and other blocking-read checkpoints remain cooperative. Cache keys need repository identity, both object IDs, byte-safe paths, modes, and relevant comparison/rendering options. `RepositorySession` may reuse the canonical worktree's object reader while Refresh rereads mutable state. Keep linked worktrees distinct even when their objects are shared. Missing local LFS content must remain retryable.

The main worker shares one active read and one replaceable pending read across history, previews, search, attribution, and quiet refresh. Preserve Git read deadlines and panic recovery. Trace `workspace::invalidate_read` at working refresh/write/empty-result boundaries; advancing a UI generation alone leaves obsolete worker computation queued. Explicit writes use `SerialExecutor::submit` or `submit_controlled` in `operations.rs`; selection cancellation must not replace, interrupt, or retry an accepted mutation. A user's explicit operation Cancel uses its separate `OperationControl`. Superseded status reads use `submit_read` so queued obsolete reads can be skipped. Mutable working previews bypass the immutable cache. Settings, recent projects, and coalesced commit drafts share their own serial writer.

For [local refresh](../../../crates/app/src/local_refresh.rs), inspect subscription roots, event/fingerprint bounds, and coalescing together with [automatic refresh scheduling](../../../crates/app/src/automatic_refresh.rs). Quiet reads wait behind foreground work, pending search, contextual file history/blame, status, and writes. Superseded reads return their events to pending work. Check repository identity, refresh epoch, and selection/status generations before applying replies; an unchanged comparison should retain its editors, query, focus, and viewport. Events and focus regain cause local reads only. Keep benchmark output outside the observed fixture so trace recording cannot generate more refresh work.

For search and file history, inspect both the app state and [core history stream](../../../crates/git-core/src/history.rs): immutable scope/anchor, continuation cursor, active cancellation, retained metadata limits, and explicit stop reasons. Compare equal amounts of scanned/returned work; a time, byte, page, or UI-retention stop is not exhaustion. File-history continuation replays a bounded rename-following prefix, so deeper pages can have different costs. [Blame and line history](../../../crates/git-core/src/blame.rs) use separate bounded core reads through the same app worker. The transient `recovery::StashBrowser` instead owns a metadata executor and preview worker/cache; include those allocations and their close-time lifetimes when measuring stash inspection.

For ordinary paging, trace [history window and cursor contracts](../../../crates/app/docs/navigation-and-refresh.md#ordinary-history-paging) through `history_paging`, `HistoryTraversal`, and `GraphCursor`. Older appends captured pages; Previous/Newest rebuild a bounded window with work linear in depth. Keep initial load, subsequent pages, backward restoration, and selected-commit retention separate in measurements. For graph work, check cancellation during preflight, each geometry row, cursor publication, and node-only fallback. Preflight alone cannot cancel later layout work. Preserve lane/edge budgets and reuse temporary frontier maps, sets, and vectors across rows; a budget fallback must not draw incomplete ancestry. Read current limits from `worker.rs` and `history_paging.rs`.

Select relevant existing regression coverage from the [app](../../../crates/app/AGENTS.md), [core](../../../crates/git-core/AGENTS.md), and [preview](../../../crates/preview/AGENTS.md) guides and the affected modules above. Follow the root final Rust gates when integrating code changes; reviewing this guidance alone does not require benchmarks or a build.

Verify passive read behavior with disposable Git fixtures that exercise roots, merges, byte-safe paths, worktrees, LFS/missing objects and configured helpers as relevant. Status must not refresh the index or invoke clean/process filters; preview files are raw bounded reads. Preserve the separate write policy that retains real Git hooks, filters, identity, and signing. No fixture command may target a user's repository. Read-only command flags are additional controls, not a complete proof; inspect actual operations and compare fixture state when changing the Git layer.

When collecting or assessing latency or memory evidence, read [measurement procedures](references/measurement.md) for existing harnesses, frame-trace boundaries, and recording requirements. Performance claims require release evidence tied to the exercised build and fixture, with raw samples and cache conditions; preserve outliers and distinguish backend from native measurements.

Prefer a narrow measured correction over another engine, persistent database, or broad cache without evidence. Once the affected behavior and required checks pass, report the result and concrete limits; repeat or broaden only for a new change, failure, or unresolved concern.
