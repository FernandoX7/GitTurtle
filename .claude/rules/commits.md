# Commits and branches

Atomic Conventional Commits, one cohesive change with its code, tests and documentation: `feat`, `fix`, `docs`, `refactor`, `perf`, `test`, `build`, `ci`, `chore` or `revert`, an optional scope, and `!` or a `BREAKING CHANGE:` footer when applicable. Stage explicit intended paths and inspect the staged diff before committing; preserve unrelated changes; never amend or rewrite published history, and never bypass hooks. Pull request titles are Conventional Commit subjects because merges are squashed.

In an interactive session the coordinator commits; in a controller session the controller commits from the returned result, so return changes without staging. Claude-authored branches use a `claude/<topic>` prefix, matching the existing `codex/<topic>` convention.
