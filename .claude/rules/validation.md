# Validation

Two gates cover Rust changes. `python3 scripts/gate.py fast` runs fmt, spelling, unused dependencies, a workspace check, and clippy plus the tests for the crates that changed, and is meant to finish in under three minutes on a warm target directory; run it before finishing any Rust change. `python3 scripts/gate.py full` runs the workspace suite, doctests, clippy, doc lints, dependency and advisory checks, snapshot verification, diff-scoped mutation testing and the release build, and is what the controller and the verifier run on a candidate. A red gate writes `.local/gate/report.md` with the failing stage, the first error as `file:line:col` and the narrowest command that reproduces it; fix the root cause, never the threshold.

Host-specific known failures are listed one test name per line in `.local/gate/known-failures.txt`; nothing else excuses a red test. Measure performance claims in release mode and record fixture, hardware, cache state and tail latency. Native interaction, package, performance and vendor claims need evidence from the affected platform and build, collected by the native-qa or performance-reviewer role; a compile or a reviewer's opinion does not replace it. Do not repeat a clean gate on unchanged code.
